## ID 규칙

문서끼리는 ID로 잇습니다. 검색창에 ID를 넣으면 관련 문서가 모두 나옵니다.

```
요구사항  REQ-E-04   →  기능  E-04-1   →  정책  P-07-04
          (영역-번호)       (요구사항-세부)      (정책 장-번호)
```

- 요구사항은 "기능 명세 ID"로 기능을, 기능은 "정책 ID"로 정책을 가리킵니다. 요구사항에서 정책으로 바로 잇지 않습니다(번호가 바뀌면 고칠 곳이 늘어남).
- 화면 번호(예: `2-02j`, `3-01`)는 피그마 와이어프레임의 화면 이름과 같습니다.

## 상태 표시

| 표시 | 뜻 |
|---|---|
| 확정 | 정해졌고 개발해도 됨 |
| [논의] | 팀에서 정해야 함 |
| [개발 확인] | 개발에서 가능 여부 · 방식 답을 받아야 함 |
| [제안] | 근거가 부족한 초안. 확인되면 표시를 지움 |

**배포 표시:** P0 기능에는 **1차**(11월 말 스토어 배포) / **2차**(12/18 MVP 완성)를 붙입니다. 삭제한 요구사항 · 기능은 번호를 다시 매기지 않고 MVP "삭제"로 남깁니다.

## 문서를 고치는 순서

회의나 결정이 나오면 **이 저장소에서** 위 문서부터 한 번씩만 고칩니다.

**MVP → 요구사항 → 기능 명세 → 정책 → 이용약관 → 와이어프레임 · 플로우차트 · IA → 팀 공지**

- MVP는 버전마다 새 파일(`mvp-v0.8.md`)로 만들고, 나머지 문서는 같은 파일을 고칩니다.
- 고친 뒤 이어진 ID끼리 상태 · MVP 포함 여부가 맞는지 확인합니다.

## 변경 기록

- 바뀐 것만 남깁니다. "현재안 유지"로 끝난 안건은 적지 않습니다.
- 근거는 **사람 이름 없이** "날짜 · 파트 · 한 줄 이유"로 적습니다. 예: `10/16 정기회의 · FE: 반경 고정보다 줌이 자연스러움`
- 줄 단위 변경은 커밋 기록(History)에 남고, 팀이 읽을 요약은 [CHANGELOG.md](CHANGELOG.md)에 모읍니다.

### 커밋 메시지

```
docs(문서): 무엇을 바꿨는지 (근거)
```

예시
- `docs(mvp): v0.6 약속 요청 자동 거절 추가 (10/18 PM)`
- `docs(기능): E-02-1 지도에서 보기 → 앱 안 지도 (10/18 PM)`
- `docs(정책): P-07-04 자동 거절 알림 추가`
