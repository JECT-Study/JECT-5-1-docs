## 2. 서비스 정의 · 타겟

### 서비스 정의

서비스명: 바꾸 (Bakku)

랜덤 굿즈를 뽑은 직후 원하지 않는 아이템을 바로 올리고, 원하는 아이템을 가진 사람과 직접 만나 교환할 수 있게 연결하는 현장 교환 서비스

- 플랫폼: 모바일 앱 (Google Play · App Store), 로그인 필수
- 핵심 가치: 서로의 교환 수요를 미리 보여줘서, 우연히 대화를 들어야만 성사되던 교환을 찾아서 하는 교환으로 바꾼다 (인터뷰 P4)
- 부가 가치: 금액 입력 · 결제 · 수수료 · 배송비 없는 교환 (인터뷰 P2 · P5)

### 핵심 타겟

- 가챠 · 랜덤 피규어 · 키링을 사고 교환이나 판매를 해본 20대 (서베이: 응답자 83%가 20대, 가챠 구매 83%)
- 거점 5곳처럼 굿즈 매장이 모인 지역을 자주 찾는 사람 (인터뷰: 홍대 3명, 용산 · 국전 2명)
- 현장 교환을 해봤거나 하고 싶었던 사람 (서베이: 경험 59%, 하고 싶었지만 못 함 29%)
- 만 14세 이상 (개발 확인: 본인인증은 사업자 등록 필요)

### 후순위 타겟

- 교환 미경험자. 76%가 "과정이 번거로워서" 안 했다 (서베이). 흐름을 단순하게 만들어 자연스럽게 유입되게 하되 초기 타겟으로 두지 않는다

### 해결할 문제

| 문제 | 근거 | MVP의 해결 방식 |
|---|---|---|
| 비인기 아이템은 교환 상대를 찾기 어렵다 | 서베이: 가장 크게 나온 불편 | 태그 검색, 원하는 아이템이 아니어도 교환 제안, 여러 아이템 첨부, 위시리스트 키워드 알림 (2차) |
| 교환 과정이 번거롭다 | 서베이: 미경험자 76%, 택배 번거로움 65% | 단계별 템플릿 입력, 요청하면 바로 채팅, 현장 교환 중심, 택배 없음 |
| 상대를 믿기 어렵다 | 서베이: 신뢰 정보 필요 87% · 인터뷰: 노쇼 중시 2명, 완료 횟수 중시 1명 | 2단계 약속, 완료 횟수, 신고 · 차단 (1차) / 매너 지표 · 노쇼 처리 (운영자 확인) · 후기 (2차), 교환 후에도 유지되는 채팅 |
| 지금 근처에 있는 상대를 모른다 | 인터뷰: "전날 글은 상대가 이미 떠남" · 서베이: 이동 30분 이내 65% | 현장 모드, 교환 지도 첫 탭 (축소하면 거점별 현장 글, 확대 · 내 위치 버튼으로 내 주변) (1차), 현장 글 반복 알림 (2차) |
| 교환하려다 구매 · 외부 거래로 빠진다 | 인터뷰: "교환 또는 판매"를 함께 적는 습관 · 서베이: 경험자 56%가 판매로 처리 | 요청에 내 아이템 첨부 필수, 신고 (1차), 금지어 · 외부 거래 경고 (2차) |

## 3. 핵심 방향

| 항목 | 결정 | 근거 |
|---|---|---|
| 중심축 | 현장 교환. 뽑은 직후 글을 올리는 것이 대표 진입 시점. **교환 지도 · 현장 모드는 1차부터** | 인터뷰 3명 지지 · 서베이 현장 교환 경험 59% |
| 배포 | 1차: 한 사이클(가입 → 글 → 지도 · 리스트 탐색 → 요청 = 채팅 → 약속 → 교환 → 완료) + 스토어 심사 필수 기능 / 2차: 탐색 편의 · 신뢰 · 안전 장치 | JECT 배포 마감 12/18 · 스토어 심사 기간 불확실 |
| 택배 교환 | 제외 | 서베이 택배 번거로움 65% · 인터뷰: 저가 가챠는 배송비가 상품보다 큼 · 사기 피해 구제 불가 |
| 판매 · 결제 | 제외, "수수료 없는 교환"을 강점으로 | 판매 중개는 사업자 등록 필요 · 서베이 경험자 56%가 판매로 처리 |
| 매칭 | 자동 매칭 없이 탐색 → 교환 요청 (바로 채팅), 태그 검색 · 위시리스트 알림으로 보완 | 인터뷰 P2 · P5 이미 검색으로 탐색 · 서베이 탐색 기능 필요 61% |
| 아이템 등록 | 1게시물 1아이템, 직접 찍은 사진 필수 | IP 이슈 회피 · 인터뷰 P5 실물 사진이 신뢰 기준 |
| 노출 | 교환 지도 (첫 번째 탭)는 현장 모드 글만, 상단 [지도 \| 리스트] 전환 (예약중 제외). 교환글 리스트 (두 번째 탭)는 전체 + 필터 · 정렬 | 10/13 PM · PD 회의 · 개발 확인 (좌표 기능 가능) · 10/16 정기회의 FE 확대 · 축소 구현 가능 |
| 교환 장소 | 희망 장소는 현재 위치 · 장소 검색 · 지도 핀. 거점은 핀 좌표로 자동 분류 (거점 5 + 미분류). 정확한 위치는 약속 · 채팅에서 | 인터뷰: 역 출구 등에서 만나는 관행 · 개발 확인 안건 1번 |
| 권한 | 위치 · 사진 · 알림은 처음 쓰는 순간에 이유와 함께 요청, 앱 시작 · 가입 때 묻지 않음 | OS 권한 팝업은 다시 띄울 수 없음 |
| 신뢰 · 운영 | 완료 횟수 공개 (1차), 매너 지표 공개 · 노쇼 · 후기 평가는 비공개 (2차). 신고 · 노쇼는 관리자 페이지 없이 운영자가 DB에서 하루 1회 확인. 누적 위반 제재 기준은 정책서 P-05 (MVP 적용 [논의]) | 노쇼 공개는 낙인 · 허위 신고 방지 · 개발 공수 |
| 도감 · 보유 목록 | 제외 (향후 확장) | 개발 확인: 아이템 DB 구축 불가 |

## 4. MVP 기능

우선순위: P0 (MVP 필수) / P1 (MVP 이후 바로) / 후순위. P0은 배포 단계로 다시 나눈다: **1차** (11월 말 스토어 배포) · **2차** (12/18 MVP 완성).

### P0 · 1차 (11월 말 스토어 배포)

기준: 한 사이클이 돌아가는 것 + 스토어 심사에 꼭 필요한 것 (신고 · 차단 · 탈퇴 · 개인정보 처리방침 · 문의하기)

| 기능 | 내용 | 화면 | 비고 |
|---|---|---|---|
| 앱 소개 | 첫 실행 시 최대 5장, 건너뛰기 가능, 권한 요청 없음 | 0-02 | 구성 · 그래픽은 PD |
| 소셜 로그인 · 가입 | 네이버 · 카카오 로그인, 중복 가입 방지, 이용약관 · 개인정보 처리방침 동의 (마케팅 수신 선택), 기본 프로필 (닉네임 2\~10자 · 생년월일 만 14세 이상 · 성별 남/여), 이메일 미수집, 로그인 유지 | 0-03 · 0-04 · 0-05 | 애플 로그인 제외 (개발 확인 안건 5번) |
