## 규칙

- **ID:** `REQ-영역-번호`
  - A 진입 · 가입 / B 교환글 작성 / C 탐색 · 교환 요청 / D 교환 요청 알림 / E 채팅 · 약속 / F 현장 교환 · 완료 / G 마이 · 설정 / H 관리자 페이지 / X 공통 / N 비기능
- **요구사항 문장:** "사용자는 \~할 수 있다" / "시스템은 \~해야 한다"
- **우선순위:** P0 = 1차 (11/27 스토어 심사) / P1 = 2차 먼저 / P2 = 2차 여유 있으면 / 이후 = MVP 뒤 백로그 (v0.5.1 10/31). 요구사항의 우선순위는 연결된 기능 중 가장 높은 것
- **MVP:** 포함 / 제외 / 논의 (삭제한 요구사항은 지우고 같은 영역 번호를 앞으로 당김, v0.4 10/26. "제외"는 남김)
- **배포:** 1차 (11/27 스토어 심사) / 2차 (12/18 MVP 완성). 기능 일부만 2차면 "1차 · 2차 (기능 ID)"
- **상태:** 확정 / 논의 / 개발 확인 / 제안 (기능 명세서와 같은 기준)
- **예외:** 그 요구사항에서 안 되는 것 · 막히는 경우
- **화면:** 와이어프레임 화면 번호
