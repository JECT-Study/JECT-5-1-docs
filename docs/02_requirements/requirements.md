## 규칙

- **ID:** `REQ-영역-번호`
  - A 진입 · 가입 / B 게시글 작성 / C 탐색 · 교환 요청 / D 교환 요청 알림 / E 채팅 · 약속 / F 현장 교환 · 완료 / G 마이 · 설정 / H 관리자 페이지 / X 공통 / N 비기능
- **요구사항 문장:** "사용자는 \~할 수 있다" / "시스템은 \~해야 한다"
- **우선순위:** P0 = 이번 출시 (12/18 애플 배포) / P1 = 출시 후 먼저 / P2 = 출시 후 여유 있으면 / 이후 = 백로그 (v0.6 11/23). 요구사항의 우선순위는 연결된 기능 중 가장 높은 것. 일부만 출시 후로 미루면 "P0 (P1: 미루는 부분)"
- **MVP:** 포함 / 제외 / 논의 (삭제한 요구사항은 지우고 같은 영역 번호를 앞으로 당김, v0.4 10/26. "제외"는 남김)
- **상태:** 확정 / 논의 / 개발 확인 / 제안 (기능 명세서와 같은 기준)
- **예외:** 그 요구사항에서 안 되는 것 · 막히는 경우
- **화면:** 와이어프레임 화면 번호

## A 진입 · 가입

### REQ-A-01
사용자는 첫 실행 시 앱 소개(최대 5장)를 보고 건너뛸 수 있다
- `P2` · MVP 포함 · 확정 · 기능 A-01-1 · 화면 0-02
- 예외: 두 번째 실행부터는 보이지 않는다.

### REQ-A-02
사용자는 소셜 계정으로 로그인 · 가입할 수 있다
- `P0` · MVP 포함 · 확정 · 기능 A-02-1 · 화면 0-03
- 예외: 이메일 · 전화번호 가입은 없다.
- 비고: 로그인 종류: 카카오 · 네이버 (개발 확인 안건 5번 · 10/20) + Apple (iOS만, v0.5.3 10/31: 애플 심사 지침 4.8)

### REQ-A-03
시스템은 소셜 계정 기준으로 기존 · 신규 회원을 구분하고 중복 가입을 막아야 한다
- `P0` · MVP 포함 · 확정 · 기능 A-03-1 · 화면 0-03
- 예외:
  - 같은 소셜 계정으로는 중복 가입할 수 없다.
  - 다른 소셜 계정으로 가입하면 별개 계정이 된다 (이메일 · 전화번호는 수집하지 않는다).

### REQ-A-04
사용자는 필수 약관(개인정보 수집 항목 · 목적 · 보관 기간)에 동의해야 가입할 수 있다. 마케팅 정보 수신 동의는 선택이다
- `P0` · MVP 포함 · 확정 · 기능 A-04-1 · 화면 0-04
- 예외: 필수 약관에 동의하지 않으면 다음 단계로 갈 수 없다.

### REQ-A-05
사용자는 닉네임 · 생년월일(필수) · 성별(선택)을 직접 입력해 프로필을 만들 수 있다. 소셜 계정에서 받을 수 있는 정보를 자동으로 채우는 것은 출시 후(P1)
- `P0` (P1: A-05-1 소셜 정보 자동 채우기) · MVP 포함 · 확정 · 기능 A-05-1, A-05-2, A-05-3 · 화면 0-05
- 예외:
  - 자동으로 채워진 값도 수정할 수 있다 (P1).
  - 만 14세 미만은 가입할 수 없다.
  - 닉네임은 중복될 수 없다.
  - 생년월일을 직접 입력하면 허위 입력은 막을 수 없다.
- 비고: 수집 가능 범위는 소셜별로 다름 (BE 10/15 문서). 소셜이 실명을 주는 경우 닉네임에 자동 입력하지 않고 직접 설정 (v0.5.3 확정). 성별은 선택, 수집 목적: 연령 · 성별별 이용 통계 (v0.5.3: 필수 → 선택). 이메일은 받지 않음 (10/20). 닉네임 규칙은 명세서

### REQ-A-06

- `P1` · MVP 포함 · 확정 · 기능 A-08-1 · 화면 0-07

## B 게시글 작성

### REQ-B-01
사용자는 지금 교환 / 일반 교환을 고른 뒤 사진(1\~5장, 앱 안 촬영 포함)과 템플릿을 단계별로(내 제품 → 받고 싶은 제품 → 희망 장소) 입력해 게시글을 작성할 수 있다
- `P0` · MVP 포함 · 확정 · 기능 B-01-1, B-01-2 · 화면 1-06, 1-07
- 예외:
  - 사진이 0장이면 게시할 수 없다.
  - 6장 이상은 첨부할 수 없다.
- 비고: 10/19 PM·PD 회의: 단계로 나눔. v0.4 (10/26): 교환 개수(1:1만 / 여러 개도 OK) 항목 삭제 · '나중에 교환' → '일반 교환'

### REQ-B-02
사용자는 게시글에 # 태그를 최대 5개 달 수 있고, 입력한 글자가 들어간 기존 태그를 사용 횟수순 자동완성으로 고를 수 있다
- `P0` · MVP 포함 · 확정 · 기능 B-02-1 · 화면 1-06, 1-03
- 예외:
  - 6개째 태그는 추가되지 않는다 (토스트로 안내한다).
  - 같은 태그는 중복해서 달 수 없다.
- 비고: 자동완성은 2차 배포 (10/20). 태그별 사용 횟수 수집 필요 (BE 요청)

### REQ-B-03
사용자는 희망 장소(필수)를 장소 검색(역 · 가게 · 주소) · 지도 핀으로 정할 수 있다
- `P0` · MVP 포함 · 확정 · 기능 B-03-1, B-03-2 · 화면 1-08
- 예외: 희망 장소 없이 게시 불가 (지도 · 거점 분류의 기준) · 기기 위치는 쓰지 않는다
- 비고: 10/19 개발 확인 안건 1번: 거점 선택 칩 삭제, 핀 좌표가 거점 다각형 안이면 그 거점으로 자동 분류 · 밖이면 미분류. 장소 검색 범위 확인 (개발 확인 안건 6번). 11/23: 현재 위치로 정하기 삭제 (기기 위치를 쓰지 않음)

### REQ-B-04
사용자는 작성 때 지금 교환을 고르면 현장 모드가 켜지고 유지 시간을 정할 수 있으며, 시간이 끝나면 일반 게시글로 바뀐다
- `P0` · MVP 포함 · 확정 · 기능 B-04-1 · 화면 1-06
- 예외:
  - 최대 3시간을 넘겨 설정할 수 없다.
  - 시간이 끝나면 자동으로 해제된다.
- 비고: 3시간 = 쇼핑몰 체류 시간 기준 (10/15) · 개발 확인 완료: 서버 자동 해제 (10/18)

### REQ-B-05
시스템은 게시글 · 태그 입력에서 금지어를 단어 목록으로 감지하면 경고를 보여줘야 한다
- `P1` · MVP 포함 · 확정 · 기능 B-05-1, B-06-2 · 화면 1-06
- 예외:
  - 게시는 막지 않는다 (경고만 한다).
  - 문맥 판단은 하지 않는다.
- 비고: 10/20: 개발 확인 안건 4번 · 문맥 판단은 LLM이 필요해 제외, 단어 목록 P-02-06 다시 정리. 2차 배포. 이번 출시는 금지어 경고 없이 신고(REQ-C-09) → 운영자 처리(REQ-H-02)로 대응

### REQ-B-06
사용자는 필수 항목을 채우면 작성 완료 즉시 게시글을 게시할 수 있다
- `P0` · MVP 포함 · 확정 · 기능 B-06-1, B-06-2 · 화면 1-06, 1-01
- 예외: 필수 항목이 빠지면 게시되지 않고, 빠진 칸 모두에 오류를 보여준다.

### REQ-B-07
사용자는 내 게시글을 수정 · 삭제하고 지금 교환을 끌 수 있다 (지금 교환 끄기는 출시 후, 그 전까지는 유지 시간이 끝나면 자동 해제)
- `P0` (P1: B-07-3 지금 교환 끄기) · MVP 포함 · 확정 · 기능 B-07-1, B-07-2, B-07-3 · 화면 1-01 · 1-03 · 5-04 ⋮ 메뉴
- 예외:
  - 예약중 게시글(약속에서 고른 첨부 게시글 포함)은 수정할 수 없다.
  - 예약중 게시글은 약속을 취소한 뒤 삭제할 수 있다.
  - 교환 완료 게시글은 삭제할 수 없다.
  - 수정하면 이 게시글이 열리거나 첨부된 채팅방에 알림이 간다.
- 비고: 10/20: 수정 제한 = 예약중. v0.4 (10/26): 제안 → 확정, 수정 알림 양쪽 · 홈 카드 ⋮에서도 수정 · 지금 교환 끄기 · 삭제

### REQ-B-08
시스템은 게시글 상태를 약속 확정 시 예약중, 교환 완료 처리 시 교환 완료, 약속 취소 시 교환 가능으로 자동 변경해야 한다
- `P0` · MVP 포함 · 확정 · 기능 B-08-1 · 화면 1-03, 5-04
- 예외:
  - 사용자가 상태를 직접 바꿀 수 없다. 교환 완료는 약속을 확정하고 교환 확인에 답해야만 된다.
  - 채팅 중에는 교환 가능을 유지한다 (여러 명과 동시에 채팅할 수 있다).
- 비고: 명세서 C.1 교환글 상태 정책과 연결

### REQ-B-09
시스템은 신고로 확인된 외부 거래 · 판매 위반을 제재해야 한다. 금지어 반복 제재는 출시 후다
- `P0` · MVP 포함 · 확정 · 기능 H-02-1, H-03-2 · 정책서 P-05-04 · 화면 H-02, H-03
- 예외: 1회 게시글 삭제 + 경고 · 2회 7일 제한 · 3회 영구 정지 (외부 거래 · 판매 확인 포함)
- 비고: 정책서 P-05-04 (기준값 확정). v0.5 (10/31): 경고 기록 · 제한은 운영자가 관리자 페이지에서 적용

## C 탐색 · 교환 요청

### REQ-C-01
사용자는 홈 헤더에서 거점(홍대 · 용산 · 건대·성수 · 신도림 · 국제전자센터(국전))을 골라 그 거점 게시글만 볼 수 있다
- `P0` · MVP 포함 · 확정 · 기능 C-01-1 · 화면 1-01a
- 예외:
  - 기기 위치를 쓰지 않는다. 위치 권한을 요청하지 않는다.
  - 거점 범위 밖 게시글은 전체에서만 보인다.
  - 고른 거점은 기기에만 기억한다. 앱을 다시 켜도 유지한다.
- 비고: 1km = 서베이 이동 30분 이내 최다 (도보 15분). v0.4 (10/26): 교환 지도 내 위치 버튼 → 탐색 위치 설정으로 바뀜. 11/23: 탐색 위치 설정(지도 · 주변 1km) → 거점 선택 (위치정보지원센터 문의 답변(일반 안내)에 따라)

### REQ-C-02
사용자는 홈 칩 줄에서 칩 하나를 골라 게시글을 보며(전체 · 지금 교환 · 일반 교환 · 카테고리), 목록은 최신순 하나로 보여준다 (정렬 메뉴 · 인기순은 출시 후. 가까운순은 제공하지 않는다)
- `P0` (출시 후: 정렬 메뉴 · 인기순) · MVP 포함 · 확정 · 기능 C-02-1, C-02-2, C-02-3 · 화면 1-01, 1-01b, 1-01c
- 예외:
  - 첫 진입 때는 모든 지역 · 첫 칩(전체 · 최신순)으로 보여준다.
  - 빈 화면은 이유별로 안내한다.
