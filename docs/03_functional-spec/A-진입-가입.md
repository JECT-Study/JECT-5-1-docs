### A-01-1 앱 소개 · 건너뛰기

> 첫 실행 시 앱 소개(최대 5장)를 보여주고 건너뛸 수 있다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 2차 | P2 | REQ-A-01 | - | 0-02 |

- **예외 · 제약:** 두 번째 실행부터는 보이지 않음

**진입** 앱 첫 실행 (A-09-1에서 분기)

**동작**
1. 앱 소개를 최대 5장 보여준다
2. 사용자는 넘기거나 [건너뛰기]를 누른다
3. 마지막 장 또는 건너뛰기 → 로그인(0-03)

**조건**
- 소개를 본 기록은 기기에 저장한다

| 예외 상황 | 처리 |
|---|---|
| 두 번째 실행 | 소개 없이 로그인으로 |
| 앱 재설치 | 첫 실행으로 보고 다시 보여줌 |

**결과** 로그인(0-03)으로 이동

### A-02-1 소셜 로그인

> 카카오 · 네이버 · Apple(iOS) 계정으로 로그인 · 가입한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-A-02 | P-04-01, P-07-03 | 0-03 |

- **예외 · 제약:** 이메일 · 전화번호 가입 없음
- **비고:** 개발 확인 안건 5번 · 10/20: 네이버 · 카카오 확정, 이메일 미수집. v0.5.3 (10/31): Apple 로그인 추가 (iOS만) — 애플 심사 지침 4.8: 소셜 로그인을 쓰면 Apple 로그인도 함께 제공해야 함 (PM J 스토어 서류 · PM 결정). Google 추가 여부는 FE가 신청 중인 소셜 로그인 확인 뒤

**진입** 로그인(0-03)

**동작**
1. 사용자가 카카오 · 네이버 · Apple(iOS에서만 보임) 로그인 버튼을 누른다
2. 소셜 인증을 마치면 계정을 확인한다 (A-03-1)
3. 기존 회원 → 첫 번째 탭 홈(1-01) / 신규 회원 → 약관 동의(0-04)

**조건**
- 소셜 계정으로만 가입한다 (카카오 · 네이버 · Apple). Apple은 iOS에서만, Android는 카카오 · 네이버
- 로그인 화면에는 약관 문구를 두지 않는다. 동의는 약관 동의(A-04-1)에서 받는다
- 이메일은 받지 않는다

| 예외 상황 | 처리 |
|---|---|
| 인증 취소 | 안내 없이 로그인 화면 유지 |
| 인증 실패 · 네트워크 오류 | 토스트 "로그인하지 못했어요. 잠시 후 다시 시도해 주세요", 로그인 화면 유지 (P-07-03) |

**결과** 홈(1-01) 또는 약관 동의(0-04)

### A-03-1 계정 확인 · 중복 가입 방지

> 소셜 계정 기준으로 기존 · 신규 회원을 구분하고 같은 계정의 중복 가입을 막는다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-A-03 | P-04-01, P-04-07, P-05-05 | 0-03 |

- **예외 · 제약:** 다른 소셜 계정으로 가입하면 별개 계정

**진입** 소셜 인증 직후 (A-02-1)

**동작**
1. 소셜 계정 고유값으로 가입 여부를 확인한다
2. 있으면 로그인, 없으면 가입 절차로 보낸다

**조건**
- 기준은 소셜 계정 고유값. 이메일 · 전화번호는 받지 않으므로 서로 다른 소셜 계정은 연결하지 않는다

| 예외 상황 | 처리 |
|---|---|
| 탈퇴한 계정으로 다시 로그인 | 탈퇴 7일 안이면 팝업 "아직 다시 가입할 수 없어요 · 탈퇴 후 7일이 지나야 같은 계정으로 다시 가입할 수 있어요 ({날짜}부터 가능)" → 로그인 화면. 이후에는 신규 가입 + 기존 노쇼 · 제재 기록 이어서 적용 (P-04-07) |
| 영구 정지 계정 | 팝업 "이용이 정지된 계정이에요 · 운영 정책 위반이 반복되어 이용이 정지됐어요. 이의가 있으면 고객 지원 이메일로 문의해 주세요" → 로그인 화면 (P-05-05) |

**결과** 첫 번째 탭 홈(1-01) 또는 가입 절차

### A-04-1 약관 동의

> 필수 약관에 동의해야 다음 단계로 가고, 마케팅 수신 동의는 선택으로 받는다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-A-04 | P-04-02, P-04-04, P-04-08, P-03-03, P-07-03 | 0-04 |

- **예외 · 제약:** 필수 약관 미동의 시 다음 단계 불가 · 마케팅 수신은 선택
- **비고:** 11/12: 하이파이 반영 — 약관 본문은 G-10-1 웹뷰 재사용 · 부분 동의 상태 · 버튼 [계속하기]

**진입** 신규 회원 소셜 인증 후

**동작**
1. 약관 목록을 보여준다
   - 필수: 서비스 이용약관 · 개인정보 수집 · 이용(항목 · 목적 · 보관 기간) · 만 14세 이상 확인
   - 선택: 마케팅 정보 수신 동의 (이벤트 · 혜택 알림)
2. 전체 동의 또는 항목별로 체크한다. 일부만 체크하면 전체 동의 칸은 "–"(부분 동의)로 표시한다
3. 항목의 > 를 누르면 약관 본문 웹뷰 (G-10-1 약관 보기 웹뷰 재사용, 상단 뒤로 + 약관 이름). 만 14세 이상 확인은 본문이 없어 > 없음
4. 필수 항목을 모두 체크하면 [계속하기] 활성 → 프로필 입력(0-05)

**조건**
- 동의 일시 · 약관 버전 · 마케팅 수신 여부를 저장한다
- 마케팅 수신에 동의하지 않아도 가입할 수 있다
- 마케팅 수신 동의는 설정에서 언제든 바꿀 수 있다 (G-06-1)

| 예외 상황 | 처리 |
|---|---|
| 필수 미체크 | [계속하기] 비활성 |
| 약관 본문 로딩 실패 | 공통 오류 (P-07-03) |

**결과** 프로필 입력(0-05)

**미결정**
- [개발 확인] 위치기반서비스 이용약관 동의 · 사업자 신고 필요 여부

### A-05-1 소셜 정보 자동 채우기

> 소셜 계정에서 받은 정보를 프로필 입력 칸에 미리 채우고, 수정할 수 있게 한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 2차 | P1 | REQ-A-05 | P-04-02 | 0-05 |

- **예외 · 제약:** 받지 못한 정보는 직접 입력

**진입** 프로필 입력(0-05) 첫 진입

**동작**
1. 소셜 로그인에서 받은 값(생년월일 · 성별 등)을 칸에 채운다
2. 제목 아래 "소셜에서 받은 정보는 미리 채워져 있어요 · 수정할 수 있어요" 안내
3. 사용자는 값을 그대로 두거나 고친다

**조건**
- 받는 항목은 소셜 로그인별 수집 범위(BE 문서)를 따른다
- 소셜에서 받은 실명은 닉네임 칸에 넣지 않는다 (닉네임은 다른 사람에게 공개되므로, v0.5.3 10/31 확정)
- 이메일은 받지 않는다 (10/20)

| 예외 상황 | 처리 |
|---|---|
| 정보를 받지 못함 (동의 안 함 · 미제공) | 빈 칸으로 두고 직접 입력 |

**결과** 채워진 상태로 A-05-2 · A-05-3 입력

### A-05-2 닉네임 입력

> 형식 · 중복 검사를 거쳐 닉네임을 정한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-A-05 | P-02-04 | 0-05 |

- **예외 · 제약:** 2\~10자 · 띄어쓰기 · 특수문자 불가 · 중복 불가
- **비고:** 11/12: 하이파이 반영 — 띄어쓰기 불가 명시(중복 확인 · 사칭 방지), 오류 문구를 글자 수 / 형식으로 나눔

**진입** 프로필 입력(0-05)

**동작**
1. 닉네임을 입력한다
2. 입력을 멈추면 형식 · 중복을 검사한다
3. 통과하면 칸 아래 "사용할 수 있는 닉네임이에요"

**조건**

- 금지어 경고는 2차 (B-05-1, P-02-04)
- 가입 후 변경은 30일에 1회 (G-03-2)

| 예외 상황 | 처리 |
|---|---|
| 글자 수 오류 (1자 · 11자 이상) | 칸 아래 "닉네임은 2~10자로 입력해주세요.", [계속하기] 비활성 |
| 형식 오류 (띄어쓰기 · 특수문자) | 칸 아래 "닉네임은 띄어쓰기 없이 한글, 영문, 숫자만 가능해요.", [계속하기] 비활성 |
| 중복 | 칸 아래 "이미 사용 중인 닉네임이에요.", [계속하기] 비활성 |

**결과** 다른 항목과 함께 저장 (A-05-3)

### A-05-3 생년월일 · 성별 입력

> 생년월일로 만 14세 이상인지 확인하고, 성별은 선택으로 받는다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-A-05, REQ-N-01 | P-04-01, P-04-03 | 0-05 |


- **예외 · 제약:** 만 14세 미만 가입 불가 · 성별은 선택 (남성 / 여성 / 비워 둠) · 허위 입력은 막을 수 없음
- **비고:** 11/12: 하이파이 반영 — 14세 미만은 팝업 · 가입 중단 대신 입력칸 아래 안내(가입 전이라 저장 없음, 약관에서 14세 확인), 성별 기본 미선택, 버튼 [계속하기]. v0.5.3 (10/31): 성별 필수 → 선택. 통계용이라 필수일 이유가 약하고, 기능과 무관한 필수 입력은 애플 심사 지침 5.1.1과 충돌할 수 있음 (PM J 스토어 서류 · PM 결정)

**진입** 프로필 입력(0-05)

**동작**
1. 생년월일을 입력한다 (자동 채우기 값이 있으면 확인만). 8자리를 다 입력하면 만 14세 이상인지 검사한다
2. 성별은 선택: 남성 / 여성 칩. 처음에는 아무것도 선택되지 않은 상태, 다시 누르면 해제 (비워 둘 수 있음)
3. 닉네임 · 생년월일을 입력하면 [계속하기] 활성 → 온보딩(0-06)

**조건**
- 만 14세 미만은 가입할 수 없다 (P-04-01)
- 성별은 선택. 고르면 연령 · 성별 통계에 쓴다
- 생년월일 · 성별은 다른 사용자에게 공개하지 않고, 가입 후 수정할 수 없다

| 예외 상황 | 처리 |
|---|---|
| 만 14세 미만 | 입력칸 아래 "만 14세 미만은 사용할 수 없어요", [계속하기] 비활성 |
| 닉네임 · 생년월일 미입력 | [계속하기] 비활성 |

**결과** 회원 생성 → 온보딩(0-06)

### A-07-1 알림 권한 요청

> 가입 마지막에 OS 알림 권한 팝업을 띄운다 (앱 자체 안내 화면 없음)

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-A-07 | - | 9-01 |


- **예외 · 제약:** 거부해도 가입 · 이용 가능, 앱 안 알림 목록에는 쌓임
- **비고:** v0.5.3 (10/31): 앱 안내 화면([알림 켜기] / [나중에]) 삭제 → OS 팝업을 바로. 거부한 뒤 알림이 필요하면 설정으로 안내 (대부분의 앱 방식, PM 결정)

**진입** 온보딩 마지막 단계 (가입 완료 화면 위)

**동작**

**조건**
- 권한 결과를 저장해 재요청(N-03-1)에 쓴다

| 예외 상황 | 처리 |
|---|---|
| OS 팝업에서 거부 | 안내 없이 가입 완료로. 다시 묻는 OS 팝업은 없고, 알림이 필요한 순간에 설정 안내 (N-03-1) |
| 푸시 토큰 발급 실패 | 사용자에게 알리지 않고 다음 실행 때 재시도 |

**결과** 가입 완료(0-07)

### A-09-1 앱 실행 시 진입 분기

> 첫 실행이면 앱 소개, 로그인 상태면 바로 첫 번째 탭, 가입 도중이면 남은 단계로 보낸다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-A-09 | P-04-01, P-07-03 | 0-01 |

- **예외 · 제약:** 로그아웃 · 탈퇴 전까지 로그인 유지 (자동 만료 없음)
- **비고:** v0.5.2 (10/31): 강제 업데이트 확인 추가. 스토어 심사 뒤에도 계속 배포하므로 옛 버전 앱이 바뀐 서버와 맞지 않을 수 있음 (PM 결정)

**진입** 앱 실행 (스플래시 0-01)

**동작**
1. 앱 버전이 서버의 최소 지원 버전보다 낮으면 강제 업데이트 팝업 "업데이트가 필요해요 · 새 버전으로 업데이트해야 바꾸를 쓸 수 있어요" [업데이트] → 스토어 앱 페이지. 닫기 · 뒤로 가기 없음, 선택 업데이트 안내는 없음 (0-01a)
2. 소개를 본 기록과 로그인 정보를 확인한다
3. 처음 → 앱 소개(A-01-1) / 로그인 상태 → 첫 번째 탭 홈(1-01) / 그 외 → 로그인(0-03)

**조건**
- 한 번 로그인하면 로그아웃(G-09-1)하거나 탈퇴(G-09-2)하기 전까지 로그인을 유지한다 (자동 만료 없음)
- 가입 도중 앱을 끄면 다음 실행 때 남은 가입 단계부터 이어서 한다

| 예외 상황 | 처리 |
|---|---|
| 영구 정지된 계정 | 정지 안내 팝업 (사유 · 문의 경로, P-05-05) 후 로그인 화면으로 |
| 탈퇴 처리된 계정 | 안내 후 로그인 화면으로 |
| 네트워크 없음 | 공통 오류 (P-07-03) + 다시 시도 |

**결과** 앱 소개 · 홈 · 로그인 · 남은 가입 단계 중 하나
