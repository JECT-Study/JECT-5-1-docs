### D-01-1 받은 요청 목록

> 게시자가 받은 요청을 카드로 모아 보고 비교한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 삭제 | - | P0 | REQ-D-01 | - | 5-05 |

- **예외 · 제약:** 대기 중 요청을 위에, 처리한 요청을 아래에
- **비고:** 10/19 삭제: 받은 요청은 채팅 목록(E-01-1)과 알림(X-01-1)으로 확인

**진입** 요청 알림 · 내 교환글 상세 [받은 요청 n건 보기] · 마이페이지 받은 요청

**동작**
1. 위에 교환글 요약 + "받은 요청 N건"
2. 요청 카드: 요청자 닉네임 · 매너 지표 · 완료 횟수 / 이 글 ↔ 첨부 아이템 / 조율 · 가능 시간 / 메시지 / 상태 배지(재요청 · 수락함 · 채팅 중)
3. 외부 거래 표현이 있는 요청은 경고 표시 (C-10-1)
4. 카드 → 요청 상세(5-05a)에서 수락 · 거절

**조건**
- 정렬: 대기 중(최신순) → 처리됨
- 취소 · 만료된 요청은 처리됨 영역에 "요청자가 취소한 요청이에요" · "만료된 요청이에요"로 표시, 누를 수 없음
- 화면을 열면 게시자 확인으로 기록해 반복 알림을 멈춘다 (D-05-1)

| 예외 상황 | 처리 |
|---|---|
| 0건 | "아직 받은 요청이 없어요" |
| 카드를 누른 사이 요청이 처리 · 취소 · 만료됨 | "이미 처리된 요청이에요" 안내 후 목록 갱신 |

**결과** 요청 상세(5-05a)

**미결정**
- [논의] 매너 지표 표시 형식 (F-06-1)

### D-02-1 요청 수락

> 게시자가 요청을 수락하면 1:1 채팅방이 열린다. 여러 요청을 동시에 수락할 수 있다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 삭제 | - | P0 | REQ-D-02, REQ-D-03 | P-07-04 | 5-05a |

- **예외 · 제약:** 약속 확정은 1명만 · 만료 · 취소된 요청은 수락 불가
- **비고:** 10/19 삭제: 요청하면 바로 채팅 (PM·PD 회의) → C-08-1

**진입** 요청 상세(5-05a) [수락하고 채팅하기]

**동작**
1. 요청 상태를 수락으로 바꾸고 1:1 채팅방을 만든다 (D-02-2)
2. 요청자에게 수락 알림, 요청자 상세 하단 버튼은 [채팅하기]로
3. 게시자는 바로 채팅방으로 이동

**조건**
- 여러 요청을 동시에 수락할 수 있다. 약속 확정은 1명만 (E-04-1)
- 확인 팝업 없이 바로 수락
- 약속이 확정돼 글이 예약중이면 다른 요청은 수락할 수 없다 (REQ-D-03)

| 예외 상황 | 처리 |
|---|---|
| 글이 이미 교환 완료 | "이미 교환이 끝난 글이에요" 안내 |
| 요청이 이미 처리 · 취소 · 만료됨 | "이미 처리된 요청이에요" 안내 |
| 요청자 탈퇴 · 차단 관계 | "수락할 수 없는 요청이에요" 안내 |
| 글이 예약중 | 수락 버튼 비활성, "약속이 잡힌 글이에요. 약속이 취소되면 다시 수락할 수 있어요" |

**결과** 채팅방(2-02), 토스트 "요청을 수락했어요. 약속을 잡아보세요"

### D-02-2 1:1 채팅방 생성

> 수락하는 순간 양쪽 아이템이 담긴 수락 카드와 함께 채팅방을 만든다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 삭제 | - | P0 | REQ-D-02 | P-07-03 | 2-02 |

- **예외 · 제약:** 요청 1건당 채팅방 1개 · 수락 없이 채팅 불가
- **비고:** 10/20 삭제: 채팅방 생성은 C-08-1(요청 전송)에 합침

**진입** 시스템 처리 (D-02-1)

**동작**
1. 요청 수락과 같은 처리 단위에서 채팅방을 만든다 (둘 중 하나만 성공하지 않게)
2. 첫 메시지로 수락 카드(교환글 ↔ 첨부 아이템)
3. 수락 카드에 [약속 잡기] 버튼 (E-01-3)

**조건**
- 요청 1건당 채팅방 1개
- 채팅방은 "방 + 참여자" 구조 (향후 그룹 채팅 대비)

| 예외 상황 | 처리 |
|---|---|
| 같은 요청에 채팅방이 이미 있음 | 새로 만들지 않고 기존 방 사용 |
| 생성 실패 | 수락도 되돌리고 공통 오류 (P-07-03) |

**결과** 채팅방 생성, 채팅 목록에 추가

### D-04-1 요청 거절 (사유 4종 · 기타 입력)

> 사유 4종 중 하나를 골라 요청을 거절하고, 사유를 요청자에게 전달한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 삭제 | - | P0 | REQ-D-04 | P-02-04, P-07-04, P-07-03 | 5-05a |

- **예외 · 제약:** 거절은 되돌릴 수 없음 · "이미 교환했어요"만 재요청 불가
- **비고:** 10/19 삭제: 요청하면 바로 채팅 (PM·PD 회의)

**진입** 요청 상세(5-05a) [거절]

**동작**
1. 사유 선택 바텀시트: 다른 아이템을 원해요 / 개수가 부족해요 / 이미 교환했어요 / 기타 (직접 입력)
2. "기타"를 고르면 입력칸(1\~50자)이 펼쳐진다
3. [거절하기] → 요청 상태 거절, 요청자에게 거절 알림 + 사유
4. "이미 교환했어요"로 거절하면 글이 바로 마감된다. 이 사유를 고르면 바텀시트에 "이 사유로 거절하면 글이 마감돼요" 안내

**조건**
- 사유를 골라야 [거절하기] 활성, 기타는 내용이 있어야 활성
- 거절한 요청은 다시 수락할 수 없다
- 재요청 가능 여부는 C-09-1 ("이미 교환했어요"만 불가)
- 직접 입력 사유는 금지어 · 외부 거래 표현 검사 대상 (P-02-04)
- 마감하면 글을 교환 완료로 바꾸고 목록에서 내린다. 앱 밖에서 한 교환이라 교환 횟수 · 매너 지표에는 반영하지 않는다

| 예외 상황 | 처리 |
|---|---|
| 요청이 이미 처리 · 취소 · 만료됨 | "이미 처리된 요청이에요" 안내 |
| 처리 실패 | 선택 유지, 공통 오류 (P-07-03) |

**결과** 받은 요청(5-05)으로, 카드 "거절함", 토스트 "요청을 거절했어요" ("이미 교환했어요"면 "요청을 거절하고 글을 마감했어요")

### D-05-1 현장 글 반복 알림

> 현장 모드 글에 새 교환 요청(채팅)이 오면 게시자가 그 채팅방을 열 때까지 반복 알림을 보낸다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 2차 | P0 | REQ-D-05 | P-07-04 | 4-01 |

- **예외 · 제약:** 현장 모드가 끝나면 반복 중단 · 간격 · 횟수는 유지 시간에 따라 다름
- **비고:** 간격 · 횟수 확정 (개발 확인 안건 2번: 1분 단위면 제약 없음, 발송 오차 최대 1분). 2차 배포

**진입** 시스템 처리 (현장 모드 글에 새 교환 요청 · 채팅방 생성, C-08-1)

**동작**
1. 새 교환 요청(채팅)이 오면 게시자에게 즉시 알림
2. 게시자가 그 채팅방을 열 때까지 일정 간격으로 다시 알림
3. 같은 글에 새 채팅이 여러 개면 하나로 묶어 "근처에서 교환을 기다리는 분이 N명 있어요"

**조건**
- 간격 · 횟수 (확정, 개발 확인 안건 2번): 15\~30분: 3분 간격 / 30분 초과\~1시간: 5분 / 1시간 초과\~3시간: 10분, 최대 5회. 발송 시각은 최대 1분 오차
- 멈추는 조건: 게시자가 그 채팅방을 엶 / 현장 모드 종료

| 예외 상황 | 처리 |
|---|---|
| 게시자가 알림을 끔 (OS 또는 설정 5-10) | 반복 푸시 없음, 앱 안 알림 목록에 1건만 |
| 요청자가 채팅방을 나감 | 그 채팅방은 반복 대상에서 제외 |

**결과** 알림 → 해당 채팅방 (2-02)

### D-06-1 보낸 요청 목록

> 내가 보낸 요청을 대기 · 수락 · 거절 · 만료 상태와 함께 모아 본다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 삭제 | - | P0 | REQ-D-06 | - | 5-06 |

- **비고:** 10/19 삭제: 보낸 요청은 채팅 목록으로 (PM·PD 회의)

**진입** 마이페이지 → 보낸 교환 요청(5-06)

**동작**
1. 요청 카드: 교환글 · 첨부 아이템 · 보낸 시각 · 상태 배지
2. 상태별 버튼

   | 상태 | 버튼 |
   |---|---|
   | 대기 중 | [요청 취소] (D-08-1) |
   | 수락 | [채팅하기] → 2-02 |
   | 거절 · 재요청 가능 | 사유 + [다시 요청하기] (C-09-1) |
   | 거절 · 재요청 불가 | 사유 + "요청 불가" |
   | 만료 · 취소 | "만료됨" · "취소함" + [다시 요청하기] (글이 거래 가능할 때만) |
   | 교환이 끝난 글 | "교환이 끝난 글이에요" |

**조건**
- 글이 교환 완료되면 대기 요청은 자동 만료 (D-07-1)
- 만료 · 취소 뒤 다시 요청은 재요청 횟수에 넣지 않는다

| 예외 상황 | 처리 |
|---|---|
| 0건 | "보낸 요청이 없어요" + [교환글 둘러보기] |
| 요청한 글이 삭제됨 | "삭제된 글이에요", 누를 수 없음 |

**결과** 카드 → 교환글 상세(1-03) 또는 채팅방

### D-07-1 요청 자동 만료

> 대기 중 요청을 현장 모드 글은 현장 모드가 끝날 때, 일반 글은 3일 무응답 시 자동 만료한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 삭제 | - | P0 | REQ-D-07 | P-07-04 | 5-05, 5-06 |

- **예외 · 제약:** 대기 중 요청만 대상 · 만료된 요청은 수락 불가
- **비고:** 10/19 삭제: 대기 중인 요청이 없어짐 (PM·PD 회의)

**진입** 시스템 처리 (스케줄)

**동작**
1. 현장 모드 글의 대기 요청 → 현장 모드가 끝나는 순간 만료
2. 일반 글의 대기 요청 → 요청 후 3일 동안 게시자 응답이 없으면 만료
3. 요청자에게 만료 알림, 보낸 요청(5-06)에 "만료됨"
4. 게시자 받은 요청(5-05) 카드는 처리됨 영역에 "만료된 요청이에요"로 남김
5. 글이 교환 완료되면 남은 대기 요청도 바로 만료

**조건**
- 글의 대기 · 수락 요청이 모두 없어지면 게시자는 글을 다시 수정할 수 있다 (B-07-1)
- 만료 뒤 같은 글에 다시 요청할 수 있다. 재요청 횟수(C-09-1)에는 넣지 않는다

**결과** 요청 상태 "만료"

### D-08-1 대기 중 요청 취소

> 요청자는 대기 중인 요청을 직접 취소할 수 있다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 삭제 | - | P0 | REQ-D-08 | - | 5-06 |

- **예외 · 제약:** 수락 · 거절 · 만료된 요청은 취소 불가 (수락 후에는 채팅방 나가기)
- **비고:** 10/19 삭제: 대기 중인 요청이 없어짐 → 채팅방 나가기(E-09-1)로 대체

**진입** 보낸 요청(5-06) 대기 중 카드 [요청 취소]

**동작**
1. 확인 팝업 "요청을 취소할까요?"
2. 요청 상태 취소, 게시자 받은 요청 카드에 "요청자가 취소한 요청이에요" 표시 (푸시 알림 없음)

**조건**
- 대기 중일 때만 가능
- 수락된 뒤에는 채팅방 나가기(E-09-1)로 처리
- 취소 뒤 같은 글에 다시 요청 가능, 재요청 횟수에 넣지 않는다

| 예외 상황 | 처리 |
|---|---|
| 누르는 사이 수락 · 거절됨 | "이미 처리된 요청이에요" 안내 후 카드 갱신 |

**결과** 카드 "취소함", 토스트 "요청을 취소했어요"
