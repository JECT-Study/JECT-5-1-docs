### E-01-1 채팅 목록

> 내가 참여한 1:1 채팅방을 최근 메시지순으로 보여준다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-E-01 | P-07-03 | 2-01 |

- **예외 · 제약:** 채팅방은 교환 요청을 보내면 바로 생김 · 보낸/받은 구분 없이 한 목록 · 차단한 상대 방은 숨김
- **비고:** v0.5.1 (10/28): 보낸 · 받은 요청 한 목록 · 새 요청 방 문구 · 글별 채팅 목록([채팅 n개 보기]) 같은 행 재사용 · 밀어서 나가기 없음 · 빈 화면 옛 수락 문구 교체 (PM 결정, PD 채팅 탭 초안 검토). v0.5.2 (10/31): 글별 채팅 목록 진입에 내 교환글 [채팅 n] 2개 이상 추가

**진입** 하단 탭 채팅(2-01) · 내 교환글 상세 [채팅 n개 보기](C-05-1) · 내 교환글 관리 [채팅 n]이 2개 이상일 때(G-02-2) → 글별 채팅 목록

**동작**
1. 보낸 요청 · 받은 요청을 한 목록에 보여준다 (받은 / 보낸 탭 없음). 최근 메시지 시각 내림차순
2. 항목: 상대 닉네임 · 교환글 대표 사진 · 마지막 메시지 1줄 · 시각 · 안 읽은 수 · 상태 배지(예약중 · 교환 완료)
3. 항목 → 채팅방(2-02), 안 읽은 수 초기화

**조건**
- 마지막 메시지가 사진이면 "사진", 시스템 메시지면 요약 문구
- 안 읽은 수 99 초과면 "99+"
- 교환이 끝난 방도 그대로 남긴다 (배지 "교환 완료")
- 내가 나간 방은 목록에서 지운다
- 상대가 나간 방은 남기고 "상대가 나갔어요" 표시
- 새 요청 방(첫 메시지가 아이템 카드)의 마지막 메시지 줄: 받은 쪽 "교환 요청이 왔어요", 보낸 쪽 "교환 요청을 보냈어요". 함께 보낸 메시지가 있으면 그 메시지 (10/28)
- 목록에서 밀어서 나가기 · 알림 끄기는 없다. 채팅방 ⋮에서만 (E-09-1) (10/28)
- 알림을 끈 방은 목록 행에 표시한다 (모양은 PD, 10/29)
- 글별 채팅 목록(내 교환글 상세 [채팅 n개 보기] · 내 교환글 관리 [채팅 n] 2개 이상): 같은 행 디자인을 쓰고, 상단만 뒤로가기 + 교환글 제목 + "채팅 n". 이 글로 열린 방 중 상대가 나가지 않은 방만, n은 상세의 "요청 n"과 같다. 하단 탭 없음 (10/28)
- 남의 글 상세 [채팅으로 가기]는 목록을 거치지 않고 그 채팅방(2-02)으로 바로 간다 (같은 글 · 같은 사람 채팅방 1개)

| 예외 상황 | 처리 |
|---|---|
| 0개 | "아직 대화가 없어요. 교환글에 요청을 보내면 채팅이 열려요" + [교환글 둘러보기] |
| 불러오기 실패 | 공통 오류 (P-07-03) |

**결과** 채팅방 진입

### E-01-2 메시지 전송 (텍스트 · 사진 · + 메뉴)

> 텍스트와 사진을 주고받고, + 메뉴에서 사진 · 약속 잡기 · 장소 보내기를 연다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-E-01, REQ-N-09 | P-02-03, P-07-04 | 2-02, 2-02h |

- **예외 · 제약:** 예약중 · 교환 완료 뒤에도 대화 유지 · 같은 글이 다른 방에서 예약중 · 교환 완료면 + 메뉴 약속 잡기 비활성 (E-11-1) · 대화가 막히는 경우는 나가기 · 차단 · 탈퇴 · 이용 제한뿐
- **비고:** 외부 거래 표현 경고(C-08-1)는 2차 (10/20). v0.5 (10/27): 약속 잡기 · 약속 취소는 + 메뉴에서 (입력창 위 버튼 삭제). v0.5.2 (10/29~10/31): 교환 완료 뒤 같은 글 다른 방도 대화 유지 · 차단당한 쪽 · 탈퇴 · 이용 제한 입력창 문구 · 교환 완료 방 + 메뉴는 사진만 · 외부 거래 경고 보낸 사람에게도

**진입** 채팅방(2-02) 입력창

**동작**
1. 텍스트 입력 후 전송, 상대에게 채팅 알림
2. 입력칸 왼쪽 + 버튼을 누르면 키보드 자리에 패널: 사진(B-01-2 재사용) / 약속 잡기(E-03-1) / 장소 보내기(E-02-1). 확정 약속이 있으면 약속 잡기 자리가 약속 취소(E-07-1)로 바뀐다. 입력창 위 약속 버튼은 없다 (10/27 PM J · PD S 합의)
3. 텍스트는 외부 거래 표현 검사 (C-08-1, 2차): 보낸 사람 · 받은 사람 화면 모두 메시지 아래 경고, 받은 사람에게는 [신고하기]도. 상단 고정 경고는 없다

**조건**
- 텍스트 1\~1,000자, 공백만은 전송 불가. 사진 1회 최대 5장
- 입력칸은 4줄까지 늘어나고 이후 스크롤
- 메시지는 실시간 전달 (REQ-N-09)
- 예약중이어도, 교환이 완료돼도 대화 유지. 같은 글의 다른 방도 대화는 유지되고 약속 잡기만 막힌다 (F-02-1)
- 교환 완료된 당사자 방의 + 메뉴는 사진만 (약속 잡기 · 장소 보내기 없음)
- 읽음 표시는 MVP 제외 (이후)

| 예외 상황 | 처리 |
|---|---|
| 전송 실패 | 말풍선 옆 !, 누르면 [다시 보내기] / [삭제] |
| 다른 분과 교환이 완료된 글의 방 | 대화 유지. + 메뉴 약속 잡기 비활성, 누르면 토스트 "교환이 완료된 글이에요" |
| 상대가 나간 방 | 입력창 대신 "상대가 대화방을 나갔어요" |
| 차단 | 차단한 쪽은 방 숨김. 차단당한 쪽은 방이 남고 입력창 대신 "대화할 수 없는 상대예요" (차단 사실은 알리지 않음, C-09-2) |
| 상대 탈퇴 · 영구 정지 | 닉네임 자리 "탈퇴한 사용자", 입력창 대신 "탈퇴한 사용자와는 대화할 수 없어요". 탈퇴 처리 전체는 G-09-2 "탈퇴하면 바뀌는 것" 표 |
| 상대가 이용 제한 중 | 입력창 대신 "지금은 대화할 수 없는 상대예요" (제재 사실은 알리지 않음). 제한이 풀리면 다시 대화 (P-05-01) |
| 내가 이용 제한 중 | 대화는 볼 수 있고 입력창 · + 메뉴 대신 "이용 제한 중이라 메시지를 보낼 수 없어요 · {해제일}까지". 누르면 사유 · 해제일 · 문의하기 (P-05-05) |

**결과** 말풍선 즉시 표시, 맨 아래로 스크롤

### E-01-3 상단 교환 카드 · 시스템 메시지

> 채팅방 위에 교환 대상과 글 상태를 고정하고, 교환 요청 · 약속 · 취소 · 완료 같은 진행 상황을 채팅 흐름에 카드로 남긴다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-E-01 | - | 2-02 |

- **예외 · 제약:** 시스템 메시지 · 수정 · 삭제 자동 메시지는 삭제할 수 없음
- **비고:** v0.4 (10/26): 첫 메시지 아이템 카드 · 입력창 위 [약속잡기]/[약속취소] · 약속 변경 제안 · 첨부 글 수정 카드 · 상단 바 매너 지표 2차. 상단 카드 상태 배지 PD 시안 반영 (10/29). v0.5 (10/27): 약속 버튼 → + 메뉴 · 수정 · 삭제 안내 = 수정 · 삭제한 사람 쪽 자동 메시지 · 상단 카드 다시 계산

**진입** 채팅방(2-02)

**동작**
1. 상단 카드: 교환글 대표 사진 · 제목 ↔ 첨부 아이템 요약 + 상태 배지. 첨부 아이템 요약은 첫 메시지 카드 첫 줄 기준 "OO 외 n개", 아이템이 삭제되면 남은 아이템으로 다시 계산 (남은 게 없으면 "⇆ 삭제된 아이템"). 상태 배지 = 교환 가능 · 예약중 · 교환 완료. 확정 약속이 있으면 "10.10 (토) 오후 3:00 · 홍대입구역" 한 줄
2. 상단 바: 상대 닉네임 · "교환 n회" (매너 지표는 2차, 프로필 사진 없음)
3. 약속은 입력칸 + 메뉴에서: 확정 약속이 없으면 약속 잡기(E-03-1), 있으면 약속 취소(E-07-1). 입력창 위 버튼은 없다 (10/27)
4. 진행 상황이 바뀌면 시스템 메시지 카드를 넣는다

| 이벤트 | 카드 · 버튼 |
|---|---|
| 교환 요청 (첫 메시지) | 아이템 카드: 첨부 아이템 한 줄씩(최대 5줄), 줄 탭 → 아이템 상세 (C-07-1 · C-07-2) |
| 약속 제안 ("교환을 제안해요") | 상대에게만 [수락하기] [거절] |
| 약속 확정 ("약속이 확정됐어요") | 시간 · 장소 · 교환해요 / 원해요. 카드 탭 → 약속 상세 [수정하기] (E-03-2) |
| 약속 변경 제안 | 상대에게만 [수락] [거절] |
| 첨부 글 · 아이템 · 요청받은 글 수정 | 수정한 사람 쪽 자동 메시지 카드 "'아이템명'을 수정했어요 [보러가기]" (내 화면 오른쪽 · 상대 화면 왼쪽). [보러가기] → 아이템 상세(C-07-2), 요청받은 글이면 교환글 상세(C-05-1) |
| 약속 취소 | 내 화면 "약속이 취소됐어요", 상대 화면 "상대가 약속을 취소했어요" (E-07-1) |
| 상대 탈퇴 | "상대가 탈퇴했어요" (푸시 없음). 확정 약속이 있었으면 "상대가 탈퇴해서 약속이 취소됐어요" (푸시 "약속이 취소됐어요"). G-09-2 |
| 제안 만료 | "응답이 없어 약속 제안이 만료됐어요" (E-10-1) |
| 약속 제안 자동 취소 (다른 방에서 먼저 확정) | "다른 분과 약속이 먼저 확정돼서 이 약속 제안은 취소됐어요", 카드 버튼 "취소됨" (E-04-1 · E-05-1) |
| 교환 확인 질문 | [못 만났어요] [교환했어요] (F-01-1, 문구는 PD 시안과 맞출 예정) |
| 교환 완료 | "교환 성공!" 카드. [후기 남기기]는 2차 |
| 다른 분과 교환 완료 ("다른 분과 교환이 완료됐어요") | - (대화 유지, 약속 잡기 비활성, F-02-1) |
| 자동 완료 | "응답이 없어 자동으로 완료됐어요. 교환하지 않았다면 마이 > 문의하기로 알려주세요" (F-03-1) |
| 운영자가 자동 완료를 되돌림 | "교환 전으로 되돌렸어요" (H-03-4) |
| 같은 글이 다른 방에서 예약중 ("다른 분과 약속이 잡혀 있어요") | - (약속잡기 비활성, E-11-1) |
| 앞 약속 취소 ("다시 약속을 잡을 수 있어요") | + 메뉴 약속 잡기 다시 활성 |
| 교환글 삭제 | "교환글이 삭제됐어요" + 상단 카드 "삭제된 글이에요" (B-07-2) |
| 첨부 글 삭제 | 지운 사람 쪽 자동 메시지 "'아이템명'을 삭제했어요"(버튼 없음) + 아이템 줄 "삭제된 아이템" + 상단 카드 다시 계산 (B-07-2) |

**조건**
- 카드 버튼은 처리 뒤 결과로 바뀐다 (예: [수락하기] → "수락했어요")
- 첫 메시지 카드에 [약속 잡기] 버튼은 없다 (10/26). 약속 잡기 · 취소는 + 메뉴 (10/27)
- 수정 · 삭제 안내는 시스템 메시지가 아니라 수정 · 삭제한 사람이 보낸 자동 메시지로 보인다. 사용자가 지울 수 없다 (10/27, PD 시안)

| 예외 상황 | 처리 |
|---|---|
| 이미 처리된 카드 버튼 | "이미 처리된 요청이에요" 안내 후 카드 갱신 |
| 교환글이 삭제됨 | 상단 카드 "삭제된 글이에요" |

**결과** 상단 카드 → 교환글 상세, 확정 약속 카드 → 약속 상세(시간 · 장소 · 교환할 물건 · [수정하기] · 내 알림 변경)

### E-02-1 장소 보내기 · 장소 카드

> 지도에서 장소를 골라 채팅에 장소 카드로 보낸다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 2차 | P2 | REQ-E-02 | P-07-03 | 2-02i, 2-02 장소 카드 |


- **예외 · 제약:** 실시간 위치 공유 아님
- **비고:** 10/18: [지도에서 보기] 버튼 → 앱 안 지도 (PM)

**진입** 채팅방 + 메뉴 → 장소 보내기(2-02i)

**동작**
1. 기본 위치는 교환글 희망 장소
2. 지도 가운데 핀 · 검색 · ◎ 내 위치로 장소를 고른다
3. [이 장소 보내기] → 채팅에 장소 카드 (지도 썸네일 · 장소 이름 · [지도에서 보기])
4. [지도에서 보기] 버튼을 누르면 앱 안 지도(1-03d 전체 화면 지도 재사용)로 장소 · 만날 곳 이름을 보여준다. 카드의 다른 곳을 눌러서는 열리지 않는다

**조건**
- ◎ 내 위치는 위치 권한 필요 (N-03-2)
- 약속 잡기 장소 기본값은 교환글 희망 장소 그대로 (장소 카드를 기본값으로 쓰지 않음, 10/29)

| 예외 상황 | 처리 |
|---|---|
| 검색 결과 없음 | "검색 결과가 없어요 · 지도를 움직여 골라 주세요" |
| 전송 실패 | 화면 유지, 공통 오류 (P-07-03) |

**결과** 채팅방에 장소 카드

### E-03-1 약속 제안

> 시간 · 장소 · 교환할 물건을 정해 약속을 제안한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-E-03 | - | 2-02b |

- **1차에서 빠지는 부분:** 약속 전 알림 설정 줄 (E-06-1) · 임박 취소 안내 문구 (E-08-1) — P1
- **예외 · 제약:** 지난 시간으로 제안 불가 · 한 채팅방에 진행 중 제안 1개
- **비고:** v0.4 (10/26): '교환할 물건' 고르기 추가 (PD 시안 '원하는 물품 직접 입력' → 첨부 아이템 중 고르기) · 진입 = 입력창 위 [약속잡기]. v0.5 (10/27): 진입 = + 메뉴 약속 잡기. v0.5.2 (10/29): 버튼 "약속 제안하기" · 장소는 지도에서 검색 또는 핀 · 주의사항에 취소 규칙

**진입** 채팅 입력칸 + 메뉴 → 약속 잡기 (확정 약속이 없을 때)

**동작**
1. 약속잡기 바텀시트

| 항목 | 필수 | 입력 방식 |
|---|---|---|
| 약속 시간 | 필수 | 지금 바로 / 날짜 · 시간(10분 단위). 지금 교환 글은 "지금 바로"가 기본 |
| 장소 | 필수 | 기본값 교환글 희망 장소. 누르면 지도에서 장소 검색 또는 핀으로 지정. 표시: 검색 = 장소 이름, 핀 = 지번 (교환글 희망 장소와 같은 규칙) |
| 교환할 물건 | 필수 | 요청에 첨부된 아이템 중 고르기 (체크, 1개 이상). 첨부가 1개면 자동 선택 · 칸 숨김 |
| 약속 전 알림 | 선택 | E-06-1. "지금 바로"면 숨김 |

2. 시트 아래 주의사항 "약속 1시간 전부터 취소하면 매너 지표에 반영돼요. 그 전에는 자유롭게 취소할 수 있어요. 약속 30분 뒤 교환했는지 물어봐요"
3. [약속 제안하기] → 채팅에 "교환을 제안해요" 카드(시간 · 장소 · 교환해요 / 원해요), 상대에게 알림

**조건**
- 날짜 범위 오늘\~7일 후
- 진행 중 제안은 한 채팅방에 1개. 새로 제안하려면 이전 제안을 취소
- 제안은 24시간 뒤 만료, 약속 시각이 더 빠르면 그 시각에 (E-10-1)
- 교환할 물건: 요청에 여러 개를 첨부했으면 이 중 실제로 교환할 것을 고른다. 고른 물건이 확정 카드에 표시되고, 교환 완료 때 고른 아이템의 글만 교환 완료된다 (F-01-2)
- 고를 수 있는 건 아직 교환 가능한 첨부 아이템만 (다른 곳에서 예약중 · 교환 완료 · 삭제된 아이템 제외)

| 예외 상황 | 처리 |
|---|---|
| 지난 시각 | 선택 불가 안내 |
| 진행 중 제안 있음 | "이전 제안을 취소하고 새로 제안할까요?" |
| 같은 글이 다른 방에서 예약중 · 교환 완료 · 교환글 삭제됨 | 약속 잡기 비활성 (E-11-1) |
| 고를 수 있는 첨부 아이템 0개 | "교환할 수 있는 아이템이 없어요" + 약속 제안 불가 |

**결과** 약속 제안 카드 표시

### E-03-2 약속 수락 · 확정 약속 수정

> 상대가 제안을 수락하면 확정되고, 확정 뒤에는 약속 상세에서 변경을 제안해 상대가 수락하면 바뀐다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-E-03 | - | 2-02b, 2-06 |

- **1차에서 빠지는 부분:** 약속 상세 2-06 · 확정 약속 수정 · 변경 제안 · 수락 시트의 약속 전 알림 설정 (P1)
- **예외 · 제약:** 제안자 본인은 수락 불가 · 변경은 상대 수락 시에만 반영 · 약속 시간이 지나면 수정 불가
- **비고:** v0.4 (10/26): 제안 단계 '수정 요청' 삭제 → 확정 약속 카드 탭 → 약속 상세 [수정하기] → 변경 제안 → 상대 수락 (PM)

**진입** "교환을 제안해요" 카드 [수락하기] · [거절] / 확정 약속 카드 탭 → 약속 상세 [수정하기]

**동작 — 제안 수락**
1. [수락하기] → 본인 약속 전 알림을 같이 정하고 확정 (E-04-1)
2. [거절] (PD 시안 [취소]) → 제안 무효, 제안자에게 알림. 다시 제안하려면 + 메뉴 약속 잡기

**동작 — 확정 약속 수정**
1. 확정 카드를 누르면 약속 상세(2-06): 시간 · 장소 · 교환할 물건 + [수정하기]
2. [수정하기] → 기존 값이 채워진 약속잡기 시트 → 고쳐서 보냄
3. 채팅에 "약속 변경을 제안해요" 카드 → 상대에게 [수락] [거절]
4. 수락하면 새 약속으로 바뀌고, 약속 전 알림(E-06-1)과 교환 확인 시점(F-01-1)을 새 시간 기준으로 다시 예약
5. 거절하거나 응답이 없으면 기존 약속 그대로

**조건**
- 제안자 본인은 자기 제안을 수락할 수 없다
- 수정은 양쪽 다 할 수 있다. 대기 중인 변경 제안은 1개
- 약속 시간이 지나면 수정할 수 없다 (교환 확인 단계로)
- 약속 취소는 약속 상세가 아니라 + 메뉴 (E-07-1, 10/27)
- 제안 단계의 "수정 요청"은 없다 (10/26). 바꾸려면 거절 후 다시 제안, 확정 뒤에는 [수정하기]
- 변경 제안은 24시간 뒤 만료, 약속 시각이 더 빠르면 그 시각에. 만료 · 거절이면 기존 약속 유지 (10/29)
- 약속 수정은 임박이어도 매너 지표에 반영하지 않는다 (상대가 수락해야 바뀌는 변경, 10/29)

| 예외 상황 | 처리 |
|---|---|
| 제안이 만료 · 취소 · 새 제안으로 바뀜 | "더 이상 유효하지 않은 약속이에요" 안내 후 카드 갱신 |
| 제안에 담긴 물건(첨부 글)이 삭제됨 | 그 제안 자동 취소 + 채팅방 안내, 그 뒤 수락은 실패 (B-07-2) |
| 약속 시각이 이미 지남 | "약속 시간이 지났어요. 새로 약속을 잡아주세요" |
| 수락 순간 다른 방에서 먼저 확정 | E-05-1 |
| 변경 제안 대기 중 [수정하기] | 비활성 + "변경 제안에 대한 답을 기다리고 있어요" |

**결과** 약속 확정 · 약속 변경 또는 기존 약속 유지

### E-04-1 약속 확정 · 예약중 전환

> 약속 요청을 수락하면 약속을 확정하고 글을 예약중으로 바꾸며, 같은 글의 다른 약속 요청 · 제안은 자동 거절하되 다른 채팅방 대화는 유지한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|

- **비고:** 10/18: 약속 요청은 여러 채팅방에서 받을 수 있고, 하나를 수락하면 나머지 자동 거절 (PM). v0.4 (10/26): 약속에서 고른 첨부 글도 예약중 · 확정 카드 탭 → 약속 상세. v0.5.2 (10/29): 확인 창을 없애고 수락 시트 안 한 줄 안내로 합침

**동작**
1. 글이 교환 가능인지 확인
2. 약속 확정 + 글 예약중 + 약속에서 고른 첨부 글도 예약중 + 알림 예약을 한 번에 처리 (10/26: 고른 첨부 글의 수정 · 삭제 · 다른 약속을 막기 위해)
3. 채팅방에 "약속이 확정됐어요" 카드(시간 · 장소 · 교환해요 / 원해요 · "약속 N분 전에 알려드릴게요"), 상단 배지 "예약중". 카드를 누르면 약속 상세(E-03-2), + 메뉴의 약속 잡기가 약속 취소로 바뀜
4. 새 교환 요청을 막는다
5. 같은 글의 다른 채팅방은 대화 유지. 그 방에 진행 중인 약속 제안은 자동 취소하고 "다른 분과 약속이 먼저 확정돼서 이 약속 제안은 취소됐어요" 안내 + 알림, 카드 버튼은 "취소됨" (P-07-04)
6. 참여자별 약속 전 알림(E-06-1)과 약속 30분 뒤 교환 확인(F-01-1)을 예약
7. 지금 교환 글이면 지금 교환 배지를 숨긴다 (시간은 계속 흐름). 약속이 취소돼 교환 가능으로 돌아왔을 때 시간이 남아 있으면 다시 보인다 (B-04-1)

| 예외 상황 | 처리 |
|---|---|
| 확정 순간 다른 방에서 먼저 확정 | E-05-1 |
| 처리 실패 | 약속 카드는 제안 상태 유지, 공통 오류 (P-07-03) |

**결과** 글 예약중, 약속 확정

### E-07-1 약속 취소

> 확정된 약속을 + 메뉴에서 확인 팝업 한 번으로 바로 취소한다 (상대 동의 없음)

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-E-07 | P-07-01, P-01-01, P-07-03 | 2-02h, 2-02d |

- **예외 · 제약:** 상대 동의 단계 없음 · 약속 1시간 전부터("지금 바로" 약속은 확정 순간부터)는 임박 취소(E-08-1) · 약속 시각이 지나면 취소할 수 없고 [못 만났어요]로 정리(F-01-1)
- **비고:** v0.5.2 (10/29): 취소 요청 · 합의 취소 · 동의 / 거절 단계와 일방 취소(옛 E-08-2)를 없애고 한 번에 취소로 합침. 취소하려는 사람은 급한 일이 생긴 경우라 요청 · 동의를 거치면 불편하고, 규칙을 약속 제안 때 미리 알린 뒤 임박만 매너 지표에 반영 (PM 결정, PD 시안과 같음)

**진입** 채팅 입력칸 + 메뉴 → 약속 취소 (확정 약속이 있을 때) · 확정 약속이 있는 방 나가기 (E-09-1)

**동작**
1. 약속 1시간 전보다 이르면 확인 팝업 "약속을 취소할까요? 상대에게 바로 알려요" [닫기] [취소하기]. 임박이면 임박 취소 팝업 (E-08-1)
2. [취소하기] → 바로 취소. 취소한 사람 · 임박 여부를 저장한다
3. 글을 교환 가능으로 (B-08-1), 약속에서 고른 첨부 글도 교환 가능. 새 요청 · 약속을 다시 받는다
4. 양쪽 시스템 메시지 (내 화면 "약속이 취소됐어요", 상대 화면 "상대가 약속을 취소했어요") + 상대에게 알림, 내 화면 토스트 "약속을 취소했어요". 상단 카드는 교환 가능으로
5. 예약된 약속 전 알림 · 교환 확인 질문을 취소한다
6. 같은 글의 다른 채팅방에 "다시 약속을 잡을 수 있어요" + 약속 잡기 다시 활성 (E-11-1)

**조건**
- 임박 전 취소는 매너 지표에 영향 없음
- 상대 화면에는 임박 취소였는지 보여주지 않는다
- 채팅방은 유지 (나가기로 취소한 경우 제외)
- 지금 교환 배지는 남은 시간이 있으면 다시 보인다 (B-04-1)

| 예외 상황 | 처리 |
|---|---|
| 이미 취소 · 완료된 약속 | "이미 처리된 약속이에요" 안내 후 카드 갱신 |
| 처리 실패 | 공통 오류 (P-07-03) |

**결과** 약속 취소, 글 교환 가능

### E-08-1 임박 취소 · 구제 신청

> 약속이 임박했을 때 취소하면 매너 지표 반영을 먼저 알리고, 합의한 취소였다면 사후에 구제를 신청할 수 있게 한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 2차 | P1 | REQ-E-08 | P-07-01, P-01-01 | 2-02e |

- **예외 · 제약:** 임박 = 시간을 지정한 약속은 1시간 전부터, "지금 바로" 약속은 확정 순간부터 (P-07-01) · 1차는 기록만, 매너 지표 감점은 2차 (F-06-1)
- **비고:** v0.5.2 (10/29): 취소 요청 거절 · 무응답 뒤 경고하던 흐름을 없애고, 임박 시점에 약속 취소를 누르면 바로 이 팝업. 둘 다 취소를 원해도 누른 사람만 기록하고 사후 구제 (신고 화면은 상대 고발용이라 섞지 않음)

**진입** 임박 시점에 + 메뉴 약속 취소(E-07-1) · 확정 약속이 있는 방 나가기(E-09-1)

**동작**
1. 팝업 "약속 1시간 전이에요. 지금 취소하면 매너 지표에 반영돼요" + "상대와 합의한 취소라면 취소 후 문의하기로 알려 주세요. 확인되면 반영하지 않아요" [약속 유지] [취소하기]
2. [취소하기] → E-07-1과 같이 취소하고 임박 취소로 기록
3. 합의한 취소였다면 마이 > 문의하기(G-08-1)의 "임박 취소 구제 신청"에 사유를 적는다 → 운영자가 관리자 페이지에서 확인 후 기록 삭제 (H-03-3)

**조건**
- 문구는 1차 · 2차 같다 ("매너 지표에 반영돼요")
- 임박 시간에 둘 다 취소를 원해도 누른 사람만 기록, 억울하면 구제 신청
- 상대 화면에는 임박 여부가 보이지 않는다
- 차단 · 탈퇴 · 이용 제한으로 인한 자동 취소, 약속 수정(E-03-2)은 반영하지 않는다

| 예외 상황 | 처리 |
|---|---|
| 이미 취소 · 완료된 약속 | "이미 처리된 약속이에요" 안내 후 카드 갱신 |

**결과** 약속 취소, 임박 취소 기록

### E-11-1 예약중 약속 잡기 제한 · 취소 시 안내

> 글이 예약중이면 같은 글의 다른 채팅방에서 약속 잡기를 막고, 약속이 취소되면 열린 채팅방 모두에 안내하고 다시 연다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-E-11 | P-07-04 | 2-02, 2-02h |

- **예외 · 제약:** 순번 없음, 먼저 약속을 확정한 사람이 우선 (선착순)
- **비고:** 10/16: 대기 걸기 삭제 (차례가 와도 교환을 보장하지 못함) · BE: 열린 방 전체 알림 가능 · 10/18: 확정 시 다른 방 약속 제안 자동 취소 (E-04-1) · v0.5.2 (10/31): 교환 완료 뒤에도 다른 방 대화 유지

**진입** 시스템 처리 (같은 글에 채팅방이 2개 이상일 때)

**동작**
1. 한 채팅방에서 약속이 확정되면(E-04-1) 같은 글의 다른 채팅방에서 + 메뉴의 약속 잡기를 비활성하고 "다른 분과 약속이 잡혀 있어요" 시스템 메시지를 남긴다. 교환이 완료되거나(F-02-1) 교환글이 삭제돼도(B-07-2) 약속 잡기는 비활성
2. 대화는 계속할 수 있다
3. 확정된 약속이 취소되면(약속 취소 E-07-1 · 나가기 E-09-1 · 차단 C-09-2 · 탈퇴 G-09-2 · 이용 제한 P-05-01) 열린 채팅방 모두에 "다시 약속을 잡을 수 있어요" 시스템 메시지 + 알림을 보내고 약속 잡기를 다시 연다
4. 먼저 약속을 확정한 사람이 우선 (선착순)

**조건**
- 순번 · 대기 없음
- 다시 열 때 "열린 채팅방" = 같은 글에서 아직 나가지 않은 채팅방

| 예외 상황 | 처리 |
|---|---|
| 교환이 완료됨 | 다시 열지 않음. 다른 채팅방은 대화 유지, "다른 분과 교환이 완료됐어요" (F-02-1) |
| 비활성 중 약속 잡기를 누름 | 예약중이면 토스트 "다른 분과 약속이 잡혀 있어요", 교환 완료면 "교환이 완료된 글이에요" |

**결과** 예약중에는 약속 1개만 유지, 취소되면 열린 채팅방 모두 다시 약속 가능
