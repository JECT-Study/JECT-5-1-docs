### B-01-1 교환글 템플릿 입력

> 정해진 10개 항목으로 교환글을 작성한다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-01 | P-02-01 | 1-06 |

- **예외 · 제약:** 1게시물 1아이템 · 필수 항목 없이 게시 불가
- **비고:** 항목 순서는 PD 컴포넌트 수정에 따라 바뀔 수 있음 (입력 방식은 확정)

**진입** 교환글 리스트 글쓰기 버튼(FAB) · 가입 완료 [첫 교환글 올리기] · 빈 화면 [글쓰기]

**동작**
1. 빈 템플릿으로 시작한다
2. 항목을 위에서부터 입력한다 (와이어프레임 1-06 순서)

| # | 항목 | 필수 | 입력 방식 |
|---|---|---|---|
| 1 | 사진 | 필수 | 1\~5장, 첫 장이 대표 (B-01-2) |
| 2 | 제목 | 필수 | 자유 입력 2\~40자 |
| 3 | 카테고리 | 필수 | 칩 하나 선택: 애니메이션 / 아이돌(케이팝) / 스포츠 / 기타 |
| 4 | 태그 | 선택 | # 입력, 최대 5개 (B-02-1) |
| 5 | 상품 상태 | 선택 | 칩: 미개봉 · 개봉 / 하자 없음 · 하자 있음 (그룹별 하나) |
| 6 | 원하는 아이템 | 필수 | 자유 입력 1\~50자 또는 "상관없음" 체크 |
| 7 | 교환 개수 | 선택 | 칩: 1:1만 / 여러 개도 OK |
| 8 | 희망 장소 | 필수 | 희망 장소 선택 화면 (B-03) |
| 9 | 현장 모드 | 선택 | 토글 + 유지 시간 (B-04-1) |
| 10 | 설명 | 선택 | 자유 입력 0\~1,000자 |

**조건**
- 입력 방식은 확정. 항목 순서는 PD 컴포넌트 수정에 따라 바뀔 수 있다
- 1게시물 1아이템
- 입력하는 동안 금지어 검사(B-05-1)와 필수 항목 검사(B-06-1)가 함께 동작

| 예외 상황 | 처리 |
|---|---|
| 작성 중 뒤로 가기 | "작성 중인 글이 사라져요" 확인 팝업 (임시저장은 P1) |

**결과** 작성 완료 → 게시(B-06-2)

### B-01-2 사진 선택 · 앱 안 촬영

> 앨범에서 고르거나 앱 안에서 촬영해 사진 1\~5장을 올린다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-01 | P-02-01 | 1-07 |

- **예외 · 제약:** 0장이면 다음 불가 · 6장 이상 선택 불가

**진입** 교환글 작성 사진 칸 · 교환 요청 [새 사진 첨부] · 채팅 + 메뉴 사진 (같은 화면 재사용)

**동작**
1. 사진 그리드 맨 앞 칸은 "촬영", 나머지는 앨범 사진
2. 고른 순서가 사진 순서이고 첫 장이 대표 사진
3. [선택 완료 (n)] → 호출한 화면으로 돌아가 채워짐

**조건**
- 교환글은 1\~5장. 실물을 직접 찍도록 안내 (IP 회피)
- 권한: 사진 · 카메라 권한은 처음 쓸 때 요청 (N-03-3)

| 예외 상황 | 처리 |
|---|---|
| 0장 | 사진 영역 아래 에러 상시 표시, [선택 완료] 비활성 |
| 6장째 선택 | 선택 불가 안내 |
| 지원하지 않는 형식 · 용량 초과 | 올릴 수 없다는 안내 |
| 제한된 사진 접근 (iOS) | 허용한 사진만 + "사진 더 선택하기" |

**결과** 호출한 화면에 사진이 채워짐

**미결정**
- [논의] 교환 요청에서 아이템 1개당 최대 장수 (3장 안)
- [개발 확인] 장당 용량 · 압축 기준 (REQ-N-10)

### B-02-1 태그 입력 · 자동완성

> #으로 태그를 달고, 입력한 글자가 들어간 기존 태그를 사용 횟수순으로 추천받는다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-02 | P-02-02, P-02-04 | 1-06 |

- **예외 · 제약:** 선택 입력 · 최대 5개 · 1개당 1\~20자 · 중복 불가 · 금지어 태그 불가

**진입** 교환글 작성 · 수정 태그 칸

**동작** (번개장터 태그 입력 방식)
1. 태그 입력칸에 글자를 입력하면 앞에 #이 붙는다
2. 입력한 글자가 들어간 기존 태그를 사용 횟수 많은 순으로 보여준다 (태그별 "N개 글" 표시)
3. 목록에서 고르면 태그가 칩으로 붙고, 입력칸이 비워져 바로 다음 태그를 입력할 수 있다
4. 목록에 없으면 "#○○ 새 태그로 추가"를 누르거나 엔터 · 띄어쓰기로 추가
5. 칩의 ✕로 삭제
6. 게시하면 태그가 저장되고 사용 횟수가 반영된다

**조건**
- 선택 입력, 글당 최대 5개, 태그 1개당 1\~20자
- 사용 횟수 = 그 태그가 달린 교환글 수
- 모든 사용자에게 같은 기준으로 추천 (개인화 없음)
- 태그는 검색(C-04-1) · 키워드 알림(G-05-2) 매칭 대상

| 예외 상황 | 처리 |
|---|---|
| 5개 다 참 | 입력칸 비활성 "태그는 5개까지 달 수 있어요" |
| 20자 초과 | 더 입력되지 않음 |
| 같은 태그 중복 | 추가하지 않음 |
| 금지어 포함 | 추가 불가, 칸 아래 안내 (B-05-1) |
| 자동완성 조회 실패 | 목록 없이 입력은 계속 가능 |

**결과** 상세(1-03)에 태그 표시

**미결정**
- [개발 확인] 사용 횟수가 같을 때 2차 정렬 · 삭제된 글 집계 여부

### B-03-1 거점 선택

> 거점 5곳 중 하나를 골라 희망 장소로 정한다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-03 | P-03-01 | 1-08 |

- **예외 · 제약:** 희망 장소 필수 · 1개만

**진입** 교환글 작성 희망 장소 칸 → 희망 장소 선택(1-08)

**동작**
1. 거점 칩(홍대 · 용산 · 건대·성수 · 신도림 · 국전)을 보여준다
2. 거점을 고르면 지도 핀이 거점 대표 위치로 옮겨진다
3. 필요하면 핀을 조정하고 만날 곳 이름을 적는다 (B-03-3)
4. [이 위치로 설정] → 좌표 · 거점이 희망 장소로 저장된다

**조건**
- 희망 장소는 필수, 1개만
- 작성 화면에는 "거점 · 만날 곳 이름"으로 표시 (예: 홍대 · 홍대입구역 9번 출구)
- 거점 반경 1km (P-03-01)
- 거점만 고르고 핀을 옮기지 않으면 거점 대표 좌표로 저장하고, 교환 지도에서 거점 묶음에 포함한다 (10/16 A안) · 거점별 대표 출구 [개발 확인]

| 예외 상황 | 처리 |
|---|---|
| 거점 목록 불러오기 실패 | 앱에 내장한 기본 5곳 표시 |

**결과** 작성 화면 희망 장소 칸에 표시

### B-03-2 장소 검색

> 장소를 입력하면 그 위치로 핀이 잡히고, 입력한 이름이 만날 곳 이름이 된다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-03 | P-03-01, P-07-03 | 1-08 |

- **예외 · 제약:** 찾는 장소가 없으면 지도에서 핀을 직접 맞춤
- **비고:** [개발 확인] 장소 검색 지도 API

**진입** 희망 장소 선택(1-08) 검색창 "장소 검색 (역 · 매장 이름)"

**동작**
1. 장소를 입력한다 (예: 서울역 1번 출구)
2. 지도 서비스로 입력한 장소를 찾아 지도 핀을 그 위치로 옮긴다
3. 결과가 여러 개면 목록에서 고르고, 고른 위치로 핀이 옮겨진다
4. 입력한 장소명이 만날 곳 이름에 채워진다 (수정 가능)
5. 핀 위치를 확인하고 [이 위치로 설정]

**조건**
- 입력 2\~30자, 줄바꿈 불가
- 검색한 장소도 반드시 핀(좌표)으로 저장된다. 그래서 모든 글이 교환 지도 · 가까운순 · 현장 모드에 쓰일 수 있다

| 예외 상황 | 처리 |
|---|---|
| 찾는 장소가 없음 | "위치를 찾지 못했어요. 지도를 움직여 핀을 맞춰 주세요" + 입력한 이름은 만날 곳 이름으로 유지 |
| 2자 미만 | "장소를 2자 이상 입력해 주세요" |
| 검색 실패 (네트워크) | 공통 오류 (P-07-03) |

**결과** 작성 화면 희망 장소 칸에 "거점(또는 지역) · 장소명" 표시

**미결정**
- [개발 확인] 장소 검색에 쓸 지도 서비스 (장소명 · 역 출구 · 주소 검색 범위)

### B-03-3 지도 핀 · 현재 위치 · 만날 곳 이름

> 지도 핀이나 현재 위치로 위치를 정하고, 만날 곳 이름을 덧붙인다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| **개발 확인** | 포함 | P0 | REQ-B-03, REQ-N-04 | P-03-01, P-03-02, P-02-04 | 1-08 |

- **예외 · 제약:** 현재 위치는 조회만, 서버에 저장하지 않음
- **비고:** [개발 확인] 핀이 거점 반경 1km 안인지 판정

**진입** 희망 장소 선택(1-08) 지도 · [📍 현재 위치로 설정]

**동작**
1. 지도 가운데 고정 핀, 지도를 움직여 위치를 정한다
2. [현재 위치로 설정] → 위치 권한 확인(N-03-2) 후 핀을 현재 위치로 옮긴다
3. 핀 아래 "만날 곳 이름"을 적는다 (예: 홍대입구역 9번 출구)
4. [이 위치로 설정] → 좌표 · 만날 곳 이름 저장. 거점 반경 안이면 그 거점으로 분류

**조건**
- 시작 위치: 위치 권한이 있으면 현재 위치, 없으면 홍대 거점
- 만날 곳 이름은 선택, 2\~30자, 금지어 검사 대상. 비워두면 지역명으로 표시
- 사용자 현재 위치는 저장하지 않고, 희망 장소 좌표만 글에 저장 (REQ-N-04)

| 예외 상황 | 처리 |
|---|---|
| 위치 권한 거부 | "거점 · 검색 · 지도 핀으로 직접 설정해 주세요" |
| 현재 위치를 못 가져옴 | "현재 위치를 찾지 못했어요" |
| 지역명 변환 실패 | "선택한 위치"로 저장, 진행은 막지 않음 |
| 만날 곳 이름에 금지어 | 칸 아래 안내, [이 위치로 설정] 비활성 |
| 지도 로딩 실패 | [다시 시도] + [목록에서 고르기] |

**결과** 작성 화면 희망 장소 칸에 "거점(또는 지역) · 만날 곳 이름" 표시

**미결정**
- [개발 확인] 핀 좌표에서 지역명 자동 추출

### B-04-1 현장 모드 설정 · 자동 해제

> 현장 모드를 켜고 유지 시간을 정하면 그 시간 동안 교환 지도에 노출되고, 끝나면 일반 글로 바뀐다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-04 | - | 1-06 |

- **예외 · 제약:** 처음 선택 15분 · 최대 3시간 · 시간이 끝나면 자동 해제
- **비고:** 개발 확인 완료: 앱을 꺼 둬도 서버가 시간이 되면 자동 해제 (10/18)

**진입** 교환글 작성 현장 모드 토글

**동작**
1. 토글을 켜면 유지 시간 칩이 나온다: 15분(처음 선택) / 30분 / 60분 / 직접 설정
2. 직접 설정은 칩 아래 − / + 줄로 15분 단위, 15분\~3시간 (처음 값 45분)
3. 끝나는 시각을 같이 보여준다 (예: 오후 4:15까지). 하나는 항상 선택된 상태
4. 게시 시점부터 유지 시간 동안 교환 지도(3-01)에 노출
5. 시간이 끝나면 현장 모드를 끄고 일반 글로 전환, 대기 요청은 만료 (D-07-1)

**조건**
- 최대 3시간 (쇼핑몰 체류 시간 기준)
- 현장 모드는 글 상태가 아니라 표시
- 지도 위치는 희망 장소 기준
- 요청이 오면 게시자에게 반복 알림 (D-05-1)
- 게시 후 다시 켜기 · 연장은 MVP 제외 (끄기는 B-07-3)

| 예외 상황 | 처리 |
|---|---|
| 3시간에서 + | + 비활성 |

**결과** 카드 · 지도에 현장 모드 배지와 남은 시간 표시

### B-05-1 금지어 검사

> 입력하는 동안 금지어를 칸 아래 표시하고, 게시할 때 서버에서 한 번 더 검사한다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-05 | P-02-02, P-02-04, P-02-06 | 1-06 |

- **예외 · 제약:** 금지어가 있으면 작성 완료 비활성 · 태그도 검사 대상

**진입** 교환글 작성 · 수정

**동작**
1. 입력을 멈추면 금지어를 검사한다 (띄어쓰기를 지우고 비교)
2. 걸린 단어를 그 칸 아래에 표시하고 작성 완료를 비활성
3. 지우면 표시가 사라지고 버튼이 다시 활성
4. 게시할 때 서버에서 같은 기준으로 한 번 더 검사

**조건**
- 검사 대상: 제목 · 원하는 아이템 · 설명 · 태그
- 모달 · 토스트는 띄우지 않는다
- 금지어 목록은 정책서 P-02-06 ([제안]), 다른 입력 칸 검사 대상은 P-02-04

| 예외 상황 | 처리 |
|---|---|
| 서버 재검사에서 걸림 | 게시하지 않고 작성 화면에 걸린 단어 표시 |
| 목록에 없는 우회 표현 | 통과. 신고로 모아 운영자가 목록에 추가 |

**결과** 금지어 없음 → 작성 완료 활성

---

### B-06-1 필수 항목 검사 · 작성 완료 버튼

> 필수 항목이 다 채워지고 금지어가 없을 때만 작성 완료를 누를 수 있다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-06 | P-02-02 | 1-06 |

- **예외 · 제약:** 사진 업로드 중에는 비활성

**진입** 교환글 작성

**동작**
1. 입력할 때마다 활성 조건을 확인한다
2. 조건: 사진 1장 이상 · 제목 2자 이상 · 카테고리 · 원하는 아이템 · 희망 장소 · 금지어 없음 · 사진 업로드 완료

**조건**
- 비활성 상태에서 모달을 띄우지 않는다
- 필수 항목 오류 문구는 그 칸을 한 번 거친 뒤에 보여준다

| 예외 상황 | 처리 |
|---|---|
| 비활성 버튼 누름 | 첫 번째 빠진 항목으로 스크롤 + 그 칸 오류 표시 |
| 사진 올리는 중 | 버튼에 "사진 올리는 중…" 표시, 비활성 |

**결과** 활성되면 게시(B-06-2)

---

### B-06-2 게시 · 교환글 리스트로 이동

> 작성 완료 즉시 게시하고 교환글 리스트 맨 위로 이동해 내 글을 보여준다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-06, REQ-B-05 | P-02-02, P-05-06, P-07-03 | 1-06, 1-01 |

- **예외 · 제약:** 별도 검수 없음 · 서버 재검사 실패 시 게시 안 함

**진입** 작성 완료

**동작**
1. 서버에서 필수 항목 · 글자 수 · 금지어를 다시 검사
2. 통과하면 상태 "교환 가능"으로 저장하고 목록 · 검색에 노출
3. 현장 모드면 교환 지도에도 노출
4. 태그 사용 횟수 반영, 키워드가 맞는 사용자에게 알림 (G-05-2)
5. 교환글 리스트(1-01) 맨 위로 이동, 내 글 카드 강조 + 토스트 "교환글을 올렸어요 · 내 글 보기"

**조건**
- 작성 화면은 뒤로 가기 기록에서 지운다

| 예외 상황 | 처리 |
|---|---|
| 서버 검사 실패 | 작성 화면 유지, 해당 칸 오류 표시 |
| 업로드 · 네트워크 실패 | 입력 내용 유지, 다시 시도 (P-07-03) |
| 이용 제한 회원 | 제한 사유 · 해제 일시 안내 (P-05-06) |

**결과** 교환글 리스트 맨 위에 내 글. 첫 게시이고 알림이 꺼져 있으면 알림 재요청 (N-03-1)

### B-07-1 내 교환글 수정

> 대기 중이거나 수락된 요청이 없을 때만 내 교환글을 수정한다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-07 | - | 1-03c |

- **예외 · 제약:** 대기 · 수락 요청이 있으면 수정 불가 · 모두 거절 · 만료되면 다시 가능

**진입** 내 교환글 상세 ⋮ → 수정 · 내 교환글 관리(5-04) ⋮

**동작**
1. 작성 화면을 기존 내용이 채워진 상태로 연다
2. 고친 뒤 저장하면 B-05-1 · B-06-1 검사를 거쳐 반영

**조건**
- 대기 중 또는 수락된 요청이 하나라도 있으면 수정 불가
- 요청이 모두 거절 · 만료 · 취소되면 다시 수정 가능
- 교환 완료 글은 수정 불가

| 예외 상황 | 처리 |
|---|---|
| 대기 · 수락 요청 있음 | 수정 메뉴 비활성 + "받은 요청이 있어 수정할 수 없어요" |
| 수정 중 요청이 들어옴 | 저장 시 서버에서 거부, 안내 후 상세로 |

**결과** 상세로 돌아가 바뀐 내용 표시

---

### B-07-2 내 교환글 삭제

> 확인 후 삭제하고, 대기 중 요청은 자동 거절한다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-07 | P-07-03 | 1-03c |

- **예외 · 제약:** 예약중 글은 약속 취소 후 삭제 · 교환 완료 글 삭제 불가

**진입** 내 교환글 상세 ⋮ → 삭제

**동작**
1. 확인 팝업 "삭제할까요? 받은 교환 요청은 자동으로 거절돼요"
2. 이 글을 내가 보낸 요청에 첨부해 둔 경우 확인 문구 추가 "보낸 요청에 첨부된 글이에요. 삭제하면 요청에서도 빠져요"
3. 글을 삭제하고 목록 · 지도 · 검색에서 뺀다
4. 대기 중 요청은 자동 거절하고 요청자에게 알린다
5. 수락돼서 열린 채팅방에는 "교환글이 삭제됐어요" 시스템 메시지를 남기고 상단 카드를 "삭제된 글"로 바꾼다
6. 내가 보낸 요청의 첨부 목록에서 이 글을 뺀다. 첨부가 하나도 안 남으면 그 요청은 자동 취소

**조건**
- 교환 가능 상태일 때만 삭제 가능

| 예외 상황 | 처리 |
|---|---|
| 예약중 | 삭제를 막고 "약속을 먼저 취소해 주세요" |
| 교환 완료 | 삭제 메뉴를 보여주지 않음 |
| 보낸 요청에서 첨부가 모두 빠짐 | 그 요청 자동 취소 (게시자 받은 요청에서 사라짐) |
| 처리 실패 | 공통 오류 (P-07-03) |

**결과** 내 교환글 관리(5-04)로 이동, 토스트 "삭제했어요"

### B-07-3 현장 모드 끄기

> 유지 시간 전에 현장 모드를 직접 끄고 일반 글로 바꾼다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-07 | - | 1-03c |

- **예외 · 제약:** 현장 모드가 켜져 있을 때만 메뉴 노출 · 다시 켜기 · 연장은 MVP 제외

**진입** 내 교환글 상세 ⋮ → 현장 모드 끄기

**동작**
1. 확인 팝업 "현장 모드를 끌까요? 교환 지도에서 사라져요"
2. 현장 모드를 끄고 교환 지도에서 뺀다
3. 반복 알림을 멈추고, 대기 요청은 만료 처리 (D-07-1과 같은 기준)

**조건**
- 현장 모드가 켜져 있을 때만 메뉴 노출
- 끈 뒤 다시 켜기 · 시간 연장은 MVP 제외

| 예외 상황 | 처리 |
|---|---|
| 이미 시간이 끝남 | 메뉴 숨김 |

**결과** 상세 유지, 현장 모드 배지 제거

### B-08-1 교환글 상태 자동 변경

> 약속 확정 · 교환 완료 · 약속 취소에 따라 글 상태를 자동으로 바꾼다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-08 | - | 1-03, 5-04 |

- **예외 · 제약:** 사용자가 상태를 직접 바꾸는 기능은 없음

**진입** 시스템 처리

**동작**

| 이벤트 | 글 상태 |
|---|---|
| 게시 | 교환 가능 |
| 약속 확정 (E-04-1) | 교환 가능 → 예약중 |
| 약속 취소 · 노쇼 신고 (E-07 · E-08 · F-04) | 예약중 → 교환 가능 |
| 교환 완료 (F-01-2) | 예약중 → 교환 완료 |

**조건**
- 교환이 완료되면 요청자가 첨부한 내 교환글도 함께 교환 완료
- 예약중이면 새 요청을 받지 않음

**결과** 목록 · 상세 · 내 교환글 관리 배지에 바로 반영
