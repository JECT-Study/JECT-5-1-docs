### B-01-1 게시글 템플릿 입력

> 지금 교환 / 일반 교환을 고른 뒤, 정해진 항목을 단계별로 입력해 게시글을 작성한다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-01 | P-02-01 | 1-06 |

- **예외 · 제약:**
  - 1게시글에는 1제품만 올릴 수 있다.
  - 필수 항목을 입력하지 않으면 게시할 수 없다.
- **비고:** 11/12: 하이파이 반영 — 항목 이름 "제목" → "제품명"(하이파이 · 교환폼과 통일, 홈 카드 · 상세에서 제목처럼 보이는 값은 그대로). 10/19 PM·PD 회의: 단계 분리 · 카테고리 "애니" → "캐릭터". 단계 화면 · 항목 순서는 PD 시안. v0.4 (10/26): 교환 개수 항목 삭제 · '나중에 교환' → '일반 교환'. v0.5.3 (10/31): 교환 개수는 10/26 결정대로 없음 (와이어프레임에 남은 칸은 수정 필요로 표시) · 상품 상태 = 미개봉 / 개봉 하나 필수, 하자는 설명에 (교환 요청 폼과 같게)

**진입** 홈 글쓰기 버튼(FAB) · 가입 완료 [첫 게시글 올리기](A-08-1, P1) · 빈 화면 [글쓰기]를 누른다

**동작**
1. 첫 화면 "언제 교환할까요?"에서 지금 교환(현장 모드, B-04-1) / 일반 교환을 고른다.
   - 지금 교환 아래에는 "지금 주변의 교환할 사람을 찾아요"가 보인다.
   - 일반 교환 아래에는 "장소 · 날짜를 정해 만나서 교환해요"가 보인다.
   - 지금 교환을 고르면 하단 버튼이 [지금 교환할 분 구하기], 일반 교환을 고르면 [일반 교환할 분 구하기]다.
2. 단계별로 입력한다.
   - 순서는 내 제품(1\~5 · 10) → 받고 싶은 제품(6) → 희망 장소(8)이다.
   - 단계 제목은 "어떤 제품을 내놓을까요?" → "어떤 제품을 받고 싶나요?" → "어디서 교환할까요?"다.
   - 상단 바 제목은 고른 방식("지금 교환" / "일반 교환")이고, 오른쪽에 [그만두기]가 있다.
   - 상단 바 아래 진행 줄은 지금 교환이 4칸(유지 시간 포함), 일반 교환이 3칸이다.
   - 단계 화면 구성 · 설명칸 위치는 PD 시안을 따른다.

| # | 항목 | 필수 | 입력 방식 |
|---|---|---|---|
| 1 | 사진 | 필수 | 1\~5장을 올린다. 첫 장이 대표 사진이다 (B-01-2) |
| 2 | 제품명 | 필수 | 2\~40자를 자유롭게 입력한다. 한 줄로 고정된다. 40자에 닿으면 더 늘지 않고, 이어서 치면 마지막 글자가 새 글자로 바뀐다 (교환폼 C-06-2와 같음) |
| 3 | 카테고리 | 필수 | 칩 하나를 고른다: 캐릭터 / 아이돌(케이팝) / 스포츠 / 기타 |
| 4 | 태그 | 선택 | 태그 칸을 누르면 열리는 "태그 추가" 화면에서 입력한다. 최대 5개까지 달 수 있다 (B-02-1) |
| 5 | 제품 상태 | 필수 | 칩 미개봉 / 개봉 중 하나가 항상 선택돼 있다 (처음에는 미개봉). 하자는 설명에 적는다 |
| 6 | 원하는 제품 | 필수 | 화면의 칸 이름은 "제품명"이다. 1\~50자를 자유롭게 입력하거나 [아무거나 상관없어요]를 체크한다. 체크하면 칸에 "아무거나 상관없어요"가 들어가고 입력할 수 없게 된다. 50자에 닿으면 더 늘지 않고, 이어서 치면 마지막 글자가 새 글자로 바뀐다 (제품명과 같음) |
| 8 | 희망 장소 | 필수 | 희망 장소 선택 화면에서 고른다 (B-03) |
| 9 | 현장 모드 | 선택 | 첫 단계에서 "지금 교환"을 고르면 켜지고, 유지 시간을 정한다 (B-04-1) |
| 10 | 설명 | 선택 | 화면의 칸 이름은 "자세한 설명 (선택)"이다. 0\~1,000자를 자유롭게 입력한다. 1,000자에 닿으면 더 늘지 않고, 이어서 치면 마지막 글자가 새 글자로 바뀐다 (교환폼 C-06-2와 같음). 에러는 없다 (금지어 경고 B-05-1은 P1) |

**조건**
- 입력 방식은 확정이다. 항목 순서는 PD 컴포넌트 수정에 따라 바뀔 수 있다.
- 1게시글에는 1제품만 올릴 수 있다.
- 교환 개수(1개씩 / 여러 개) 항목은 없다 (10/26).
  - 몇 개를 줄지는 요청자가 내 게시글을 여러 개 붙여 정한다 (C-06-2).
  - 실제 교환할 제품은 약속 때 고른다 (E-03-1).
  - 게시자 선호는 채팅에서 조율한다.
- 칸에서 벗어날 때와 [다음] · [작성 완료]를 누를 때 필수 항목 검사(B-06-1)가 동작한다. 금지어 경고(B-05-1)는 P1이다.

| 예외 상황 | 처리 |
|---|---|
| 작성 중 [그만두기] · 뒤로 가기 | "작성 중인 게시글이 사라져요" 확인 팝업을 띄운다 (임시저장 없음) |
| 이용 제한 중 | 글쓰기 대신 사유 · 해제일 · 문의를 안내한다 (P-05-05) |

**결과** 작성을 완료하면 게시한다 (B-06-2)

### B-01-2 사진 선택 · 앱 안 촬영

> OS 기본 사진 선택 창에서 고르거나 앱 안에서 촬영해 사진 1\~5장을 올린다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-01 | P-02-01 | 1-07 |

- **예외 · 제약:**
  - 5장이 차면 더 추가할 수 없다.
  - 앨범(사진) 권한은 요청하지 않는다.
- **비고:** v0.4 (10/26): PD 시안 반영 — 요청 아이템 장수는 교환글과 같은 1\~5장으로 확정. 11/11: 앱이 직접 만든 사진 그리드 화면 → **OS 기본 사진 선택 창**으로 변경 (FE 답변 · PM 결정). 이유 = 앨범 권한이 필요 없어 권한 거부 · 일부 사진만 허용 예외가 사라짐, 세 진입점을 공통 기능 하나로 구현 (FE: Expo expo-image-picker)

**진입** 게시글 작성 사진 칸 · 교환폼(새로 작성하기) 사진 칸 · 채팅 + 메뉴 사진 선택에서 들어온다 (같은 기능 재사용)

**동작**
1. 사진 칸(또는 채팅 + 메뉴 사진 선택)을 누르면 바텀시트(1-07)가 열린다.
   - 시트 제목은 "제품 사진 추가"다.
   - 안내 "사진을 추가할 방법을 선택하세요."와 [앨범에서 선택하기] / [카메라로 촬영하기]가 보인다.
   - 실물 촬영 안내는 시트에 넣지 않는다. 첫 장이 대표라는 것은 썸네일의 "대표 사진" 표시로 알린다 (11/23 PM).
   - 새 게시글 작성으로 처음 들어왔을 때는 화면에 도착하자마자 이 바텀시트를 바로 연다.
   - 수정(B-07-1) 화면으로 들어오거나 다음 단계에서 뒤로 돌아왔을 때는 열지 않는다 (11/17, PD 하이파이).
2. [앨범에서 선택하기]를 누르면 OS 기본 사진 선택 창이 열린다. 여러 장 고를 수 있고, 고를 수 있는 장수는 남은 장수(5 − 이미 붙인 장수)까지다.
3. [카메라로 촬영하기]를 누르면 카메라가 실행되고, 찍은 사진 1장이 추가된다 (카메라 권한은 N-03-3).
4. 고르거나 찍으면 호출한 화면으로 돌아가 채워진다.
   - 카메라 칸 바로 옆(가장 왼쪽)부터 오른쪽으로 한 장씩 추가된다.
   - 가장 왼쪽 사진이 대표 사진이고, 썸네일에 "대표 사진"이 표시된다 (11/17).

**조건**
- 게시글 · 교환폼은 1\~5장을 올린다. 실물 사진을 올리는 것이 원칙이다 (IP 회피, P-02-01). 화면에 따로 안내하지는 않는다 (11/23 PM).
- 5장 제한은 OS 선택 창의 선택 수 제한으로 걸고, 앱에서 기존 첨부 수를 포함해 한 번 더 검사한다.
- 사진 그리드 · 정렬 · 앨범 바꾸기 등 선택 화면 구성은 OS 기본 창을 따른다.

| 예외 상황 | 처리 |
|---|---|
| 이미 5장인데 사진 칸을 누름 | 토스트 "이미지는 최대 5장까지 첨부할 수 있어요"를 띄운다 (시트는 열지 않는다) |
| 지원하지 않는 형식 · 용량 초과 | 토스트 "올릴 수 없는 사진이에요"를 띄운다 |
| OS 선택 창 · 카메라에서 취소 | 아무것도 바뀌지 않고 호출한 화면으로 돌아간다 |
| 카메라 권한 거부 | N-03-3 |

**결과** 호출한 화면에 사진이 채워진다

**미결정**
- [개발 확인] 장당 용량 · 압축 기준 (REQ-N-10)
- [개발 확인] OS 선택 창에서 고른 순서가 첨부 순서로 유지되는지 (가장 왼쪽 = 대표 사진)

### B-02-1 태그 입력 · 자동완성

> "태그 추가" 화면에서 태그를 달고, 입력한 글자가 들어간 기존 태그를 사용 횟수순으로 추천받는다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-02 | P-02-02, P-02-04 | 1-06 |

- **예외 · 제약:**
  - 태그는 선택 입력이다.
  - 최대 5개까지 달 수 있다.
  - 태그 1개는 1\~20자다.
  - 같은 태그는 다시 달 수 없다.
  - 금지어가 든 태그는 경고만 보여준다 (막지 않음, B-05-1, P1).
- **비고:** 11/22: 태그 입력을 2차 → 1차로 (FE 화면 · BE 저장 이미 있음, FE 질문 · 11/22 PM). 자동완성은 2차 배포 (10/20). 태그 금지어 경고는 P1 (B-05-1)

**진입** 게시글 작성 · 수정 화면의 태그 칸("#제품명, #캐릭터명, #작품명")을 누르면 별도 화면 "태그 추가"가 열린다

**동작** (번개장터 태그 입력 방식)
1. "태그 추가" 화면에는 위에서부터 [✕] · 입력칸("태그 입력 (최대 5개)") · 안내 2줄이 있다.
   - 안내 첫 줄은 "장르, 종류 등 제품을 설명할 수 있는 태그를 작성해주세요"다.
   - 안내 둘째 줄은 "제품과 관련 없는 태그를 입력하면 제재를 받을 수 있어요."다.
2. 입력칸 앞에는 #이 붙어 있다.
3. 글자를 입력하면 입력한 글자가 들어간 기존 태그를 사용 횟수 많은 순으로 보여준다 (사용 횟수 숫자는 표시하지 않음, v0.5.3 와이어프레임 기준).
   - 목록 맨 위에는 입력한 글자 그대로의 태그가 보인다.
   - 입력한 글자와 겹치는 부분은 강조한다.
4. 목록에서 고르면 태그가 입력칸 아래에 칩으로 쌓이고, 입력칸이 비워져 바로 다음 태그를 입력할 수 있다.
5. 맞는 기존 태그가 없으면 목록에 입력한 글자 그대로의 태그만 보이고, 누르거나 엔터 · 띄어쓰기로 추가한다.
6. 칩의 ✕를 누르면 삭제된다.
7. 칩이 쌓이면 하단에 [태그 n개 추가하기]가 보인다 (n은 쌓인 칩 수). 누르면 작성 화면으로 돌아가 태그 칸에 반영된다.
8. 게시하면 태그가 저장되고 사용 횟수가 반영된다.

**조건**
- 태그는 선택 입력이다.
- 게시글 하나에 최대 5개까지 달 수 있다.
- 태그 1개는 1\~20자다.
- 사용 횟수는 그 태그가 달린 게시글 수다 (삭제된 게시글은 빼고, 교환 완료 게시글은 포함한다). 사용 횟수가 0개인 태그는 추천하지 않는다.
- 추천 순서는 사용 횟수가 많은 순이고, 같으면 이름순이다. 추천은 기본 10개 · 최대 20개다 (몇 줄 보일지는 FE).
- 모든 사용자에게 같은 기준으로 추천한다 (개인화 없음).
- 태그는 검색(C-03-1) · 키워드 알림(G-05-2, P2)의 매칭 대상이다.

| 예외 상황 | 처리 |
|---|---|
| 5개가 찬 상태에서 6개째 추가 | 추가되지 않고 토스트 "태그는 최대 5개까지 추가할 수 있어요."가 뜬다 |
| 20자 초과 | 더 입력되지 않는다 |
| 같은 태그 중복 | 추가하지 않는다 |
| 금지어 포함 (P1) | 추가는 되고 칸 아래에 경고만 보인다 (B-05-1). 금지어가 든 태그는 추천 목록에 나오지 않는다 |
| 자동완성 조회 실패 | 목록 없이 입력은 계속할 수 있다 |

**결과** 상세(1-03)에 태그가 표시된다

### B-03-1 장소 검색

> 지도 화면 위 검색창에서 장소를 찾아 고르면, 그 장소가 교환 장소 칸에 바로 들어간다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-03 | P-03-01, P-07-03 | 1-08 |

- **예외 · 제약:** 찾는 장소가 없으면 지도에서 핀을 직접 맞춘다.
- **비고:** 개발 확인 안건 6번: 네이버 지도 API로 역 · 가게 · 주소 모두 가능 (지역 검색 + Geocoding 결과 통합). 11/17: PD 하이파이 반영 — 검색 결과를 고르면 지도로 돌아가지 않고 교환 장소 화면 칸에 바로 들어감 · 1자 입력은 오류 없이 목록만 안 보여줌 · 결과 없음 문구는 PD 문구로. 11/23: 거리 표시 · 거리순 정렬 삭제 (기기 위치를 쓰지 않음)

**진입** 교환 장소 지도 화면(B-03-2) 위 검색창 "장소, 지하철, 주소 검색"을 누르면 검색 화면으로 간다 (들어가면 키보드가 바로 열린다)

**동작**
1. 장소를 입력한다 (예: 서울역 1번 출구).
   - 2자 이상이면 바로 일치하는 장소 목록이 나온다 (자동완성).
   - 1자일 때는 오류 없이 목록을 보여주지 않는다.
   - 키보드 [검색] · [done]을 누르면 키보드만 내려가고 목록은 그대로 둔다 (v0.5.3 10/31).
2. 네이버 지도 API(지역 검색 + Geocoding)로 역 · 가게 · 주소를 찾는다.
3. 목록에는 장소 이름 · 주소 · 분류가 보인다. 입력한 글자와 겹치는 부분은 강조한다.
   - 거리는 표시하지 않는다 (기기 위치를 쓰지 않음, 11/23).
   - 목록 순서는 정확도순(검색 API가 준 순서) 하나다.
4. 목록에서 장소를 고르면 지도로 돌아가지 않고 교환 장소 화면으로 돌아가, 장소 설정 칸에 장소 이름이 들어간다. 좌표는 그 장소 좌표로 저장한다 (11/17, PD 하이파이).

**조건**
- 입력은 최대 30자이고, 줄바꿈은 할 수 없다.
- 검색한 장소도 반드시 좌표로 저장된다. 그래서 모든 게시글이 거점 분류에 쓰일 수 있다.

| 예외 상황 | 처리 |
|---|---|
| 찾는 장소가 없음 | 목록 자리에 "일치하는 장소가 없어요."를 보여준다. 뒤로 가서 지도에서 핀을 직접 맞출 수 있다 |
| 검색 실패 (네트워크 · 서버) | 공통 오류를 보여준다 (P-07-03): "장소를 불러오지 못했어요." + "잠시 후 다시 시도해 주세요." + [다시 시도]. 네트워크가 없으면 "인터넷에 연결할 수 없어요." + "Wi-Fi 또는 모바일 데이터 연결 상태를 확인한 후 다시 시도해 주세요." + [다시 시도]를 보여준다 |

**결과** 교환 장소 화면 장소 설정 칸에 장소 이름이 표시된다 (P-03-04). 거점 분류는 좌표에 따라 자동으로 정해진다 (B-03-2)

### B-03-2 교환 장소 화면 · 지도 핀 · 상세 주소

> 교환 장소 화면에서 장소를 고르고(지도 핀 또는 검색), 필요하면 상세 주소를 덧붙인다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-03, REQ-N-04 | P-03-01, P-03-02, P-02-04 | 1-08 |

- **예외 · 제약:** 기기 위치를 쓰지 않는다. 위치 권한을 요청하지 않는다.
- **비고:** 10/19 개발 확인 안건 1번: 핀이 거점 다각형 안이면 자동 분류 · 밖이면 미분류. 11/17: PD 하이파이 반영 — 교환 장소 화면(장소 설정 칸 + 상세 주소) → 지도 화면(검색창 · 거점 칩 · 핀 · [장소 선택하기]) 구조, "만날 곳 이름" → "상세 주소"로 이름 변경 · 최대 30자 유지, 지도 하단 · 칸 표기는 P-03-04 기준. 11/23: 현재 위치 버튼 · 현재 위치로 시작 · 위치 권한 분기 삭제, 지도 첫 화면 순서 · 거점 이름 표시 추가 (기기 위치를 쓰지 않음)

**진입** 게시글 작성 마지막 단계 "어디서 교환할까요?" (교환 장소 화면)

**동작**
1. 교환 장소 화면에는 [장소 설정] 칸("교환하고 싶은 장소를 선택해주세요") + 상세 주소(선택, "교환하고 싶은 장소의 상세한 주소를 알려주세요.") + [작성 완료]가 있다.
2. 장소 설정 칸을 누르면 지도 화면으로 간다. 위에서부터 [✕] · 검색창(B-03-1) · 거점 칩(홍대 · 용산 · 건대·성수 · 신도림 · 국제전자센터(국전)) · 지도 · 하단 주소 · [장소 선택하기]가 놓인다.
3. 지도 가운데에 고정 핀이 있다.
   - 지도를 끌어 움직이면 핀 위치가 바뀌고, 하단 주소가 바로 바뀐다.
   - 처음 들어오면 "지도를 움직여서 선택해보세요" 안내가 뜨고, 지도를 움직이면 사라진다.
4. 거점 칩을 누르면 그 거점 중심으로 지도가 이동한다. 지도만 움직이고 장소가 정해지지는 않는다.
5. 핀이 거점 범위 안이면 하단 주소 위에 거점 이름이 보인다. 밖이면 표시가 없다.
6. [장소 선택하기]를 누르면 교환 장소 화면으로 돌아가 장소 설정 칸에 구 + 동 + 번지가 들어간다 (P-03-04).
   - 게시하면 서버가 좌표로 거점을 자동 분류한다. 핀이 거점 범위 안이면 그 거점이고, 밖이면 어떤 거점에도 속하지 않는다 (C-01-1).
   - 거점 범위 밖이어도 [장소 선택하기]와 게시는 그대로 할 수 있다.
7. 상세 주소를 적는다 (선택, 예: AK 플라자 주변, 협의 가능해요).

**조건**
- 지도 첫 화면은 이미 고른 장소가 있으면 그 위치다. 없으면 마지막으로 고른 거점이고, 그것도 없으면 홍대다.
- 지도 하단 주소는 1줄 지번 · 2줄 도로명이다 (P-03-04).
- 장소 설정 칸에는 검색으로 고르면 장소 이름, 핀으로 고르면 구 + 동 + 번지가 들어간다. 게시글 상세에 보이는 표기와 같다 (P-03-04).
- 상세 주소는 선택이고, 2\~50자다 (11/23, 30자 → 50자). 게시글 상세 지도 아래 장소 메모로 한 줄 보인다 (C-05-1).
- 기기 위치는 쓰지 않는다. 사용자가 고른 교환 장소만 게시글에 저장한다 (REQ-N-04).

| 예외 상황 | 처리 |
|---|---|
| 장소를 고르지 않고 [작성 완료] | 장소 설정 칸 아래에 "교환 장소를 선택해주세요."가 보인다 (B-06-1) |
| 지도 로딩 실패 | [다시 시도]를 보여주고, 검색으로 고를 수 있다 |
| 지도 화면 [✕] | 바꾸지 않고 교환 장소 화면으로 돌아간다 |

**결과** 교환 장소 화면에 장소와 상세 주소가 표시된다. 게시글 상세에는 장소 이름(검색한 경우) 또는 구 + 동 + 번지(핀만 옮긴 경우)와, 지도 아래 상세 주소(장소 메모)가 보인다 (C-05-1, 10/27)

**미결정**
- [개발 확인] BE 칸 길이 50자 (상세 주소 2\~50자)
- [개발 확인] (FE) 네이버 지도 SDK의 현재 위치 기능을 끄고 위치 권한 요청 없이 지도를 쓸 수 있는지

### B-06-1 필수 항목 검사 · 작성 완료 버튼

|---|---|---|---|---|---|

**동작**

   - 제품명 2자 이상
   - 카테고리
   - 원하는 제품
   - 희망 장소
   - 사진 업로드 완료
3. 모두 통과하면 다음 단계로 간다 (마지막 단계면 게시 B-06-2). 빠진 칸이 있으면 그 칸들의 오류 문구를 한 번에 모두 보여주고 그중 가장 위 칸으로 스크롤한다.

**조건**
- 버튼 기준은 아래와 같다. 앱의 다른 기능도 이 기준을 따른다 (11/23).
  - 체크하거나 하나를 고르는 화면은 고르기 전까지 버튼을 누를 수 없다. 약관 동의 · 유지 시간 선택 · 내 게시글 고르기 · 이유 선택 · 탈퇴 확인 체크가 여기에 든다.
  - 여러 칸을 채우는 작성 화면은 버튼을 항상 누를 수 있다. 누르면 빠진 칸을 알려준다. 내 제품 정보 · 받을 제품 정보 · 교환 장소 · 교환 요청 새로 작성 폼이 여기에 든다.
  - 칸이 하나이고 입력하는 동안 칸 아래에 바로 오류가 보이는 화면은 조건이 맞을 때까지 버튼을 누를 수 없다. 닉네임 입력 · 닉네임 수정 · 생년월일 · 신고 "기타" 내용 · 검색어가 여기에 든다.
- 오류는 모달이 아니라 칸 아래 문구로 보여준다.
- 글자 칸 오류는 그 칸을 한 번 거친 뒤(칸에서 벗어날 때) 보여준다. 입력하는 중에는 띄우지 않는다. 버튼을 누르면 아직 안 거친 칸까지 모두 검사한다.

| 예외 상황 | 처리 |
|---|---|
| 빠진 칸이 있는 채로 버튼 누름 | 빠진 칸 모두에 오류를 표시하고, 그중 가장 위 칸으로 스크롤한다 |
| 사진 0장 | 사진 칸 아래에 "사진을 업로드해주세요."가 보인다 |
| 제품명 비어 있음 | 칸 아래에 "제품명을 입력해주세요."가 보인다 |
| 제품명 1자 | 칸 아래에 "제품명은 2자 이상 입력해주세요."가 보인다 |
| 카테고리를 고르지 않음 | 칸 아래에 "카테고리를 선택해주세요."가 보인다 |
| 원하는 제품을 적지도, [아무거나 상관없어요]를 고르지도 않음 | 받을 제품 제품명 칸 아래에 "제품명을 입력해주세요."가 보인다 (하이파이 '받을 굿즈 정보-제품명-에러', 11/23) |
| 교환 장소를 고르지 않음 | 장소 설정 칸 아래에 "교환 장소를 선택해주세요."가 보인다 (B-03-2) |
| 사진 올리는 중 | 버튼에 "사진 올리는 중…"이 표시되고, 누를 수 없다 |

**결과** 빠진 칸이 없으면 다음 단계로 가거나 게시한다 (B-06-2)

### B-06-2 게시 · 올린 게시글 상세로 이동

> 작성 완료 즉시 게시하고 올린 게시글 상세로 이동한다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-06, REQ-B-05 | P-02-02, P-05-05, P-07-03 | 1-06, 1-01 |

- **예외 · 제약:**
  - 별도 검수는 없다.
  - 서버 재검사에 실패하면 게시하지 않는다.

**진입** 작성 완료

**동작**
1. 서버에서 필수 항목 · 글자 수 · 금지어(B-05-1, P1)를 다시 검사한다.
2. 통과하면 상태 "교환 가능"으로 저장하고 목록 · 검색에 보이게 한다.
3. 지금 교환 게시글이면 홈 목록에 "지금 교환" 배지로 보인다.
4. 태그 사용 횟수를 반영한다. 키워드가 맞는 사용자에게 알림을 보낸다 (G-05-2, P2).
5. 올린 게시글 상세(1-03)로 이동한다. 뒤로 가기를 누르면 홈으로 간다 (v0.5.3 10/31: 홈 맨 위 + 토스트 → 상세, 와이어프레임 기준).

**조건**
- 작성 화면은 뒤로 가기 기록에서 지운다.

| 예외 상황 | 처리 |
|---|---|
| 서버 검사 실패 | 작성 화면을 유지하고, 해당 칸에 오류를 표시한다 |
| 업로드 · 네트워크 실패 | 입력 내용을 유지하고, 다시 시도할 수 있다 (P-07-03) |
| 이용 제한 회원 | 제한 사유 · 해제 일시를 안내한다 (P-05-05) |

**결과** 올린 게시글 상세로 간다. 첫 게시이고 알림이 꺼져 있으면 알림 꺼짐 안내를 보여준다 (N-03-1)

### B-07-1 내 게시글 수정

> 예약중 · 교환 완료가 아닐 때 내 게시글을 수정한다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-07 | - | 1-01 · 1-03 · 5-04 ⋮ 메뉴 |


- **예외 · 제약:**
  - 예약중 게시글(약속에서 고른 첨부 게시글 포함)은 수정할 수 없다.
  - 교환 완료 게시글은 수정할 수 없다.
- **비고:** 10/20: 제한 조건 '예약중'. v0.4 (10/26): [제안] → 확정, 수정 알림을 첨부된 방까지 넓힘 (요청은 원본 글과 연결). v0.5 (10/27): 수정 안내 = 수정한 사람 쪽 자동 메시지 (시스템 메시지 아님, PD 시안)

**진입** 내 게시글 상세 ⋮ · 홈 내 게시글 카드 ⋮ · 내 게시글 관리(5-04) ⋮에서 수정을 누르거나, 요청 제품 상세 ⋮에서 [수정하기]를 누른다 (C-07-2, 저장 후 제품 상세로). 같은 ⋮ 메뉴에 [교환 완료로 바꾸기]가 있다 (교환 가능 게시글만, G-02-3)

**동작**
1. 작성 화면을 기존 내용이 채워진 상태로 연다.
2. 고친 뒤 저장하면 B-06-1 검사를 거쳐 반영한다 (금지어 경고 B-05-1은 P1).
3. 이 게시글로 열린 채팅방과 이 게시글이 요청에 첨부된 채팅방에 내 쪽 자동 메시지 "'제품명'을 수정했어요 [보러가기]"가 올라가고, 상대에게 정보 변동 알림이 간다 (E-01-3 · X-01-1).
   - [보러가기]를 누르면 첨부된 방에서는 제품 상세(C-07-2)로, 요청받은 게시글의 방에서는 게시글 상세(C-05-1)로 간다 (10/27).
4. 저장 전 확인 팝업은 없다.

**조건**
- 예약중(약속 확정) 게시글은 수정할 수 없다.
  - 약속에서 교환할 제품으로 고른 첨부 게시글도 예약중이 되어 수정할 수 없다 (E-04-1).
  - 약속이 취소되면 다시 수정할 수 있다.
- 교환 완료 게시글은 수정할 수 없다.
- 자동 메시지 · 알림은 내용이 하나라도 바뀌면 보낸다 (사진만 바뀌어도). 바뀐 게 없으면 보내지 않는다.
- 자동 메시지 · 알림은 상대가 아직 채팅방에 남아 있는 방에만 보낸다.
- 지금 교환은 수정으로 바꿀 수 없다 (다시 켜기 · 연장 없음, 끄기 B-07-3은 P1).

| 예외 상황 | 처리 |
|---|---|
| 예약중 | 수정 메뉴를 누를 수 없고 "약속이 잡힌 게시글은 수정할 수 없어요"가 보인다 |
| 수정 중 약속이 확정됨 | 저장할 때 서버에서 거부하고, 안내한 뒤 상세로 간다 |

**결과** 상세로 돌아가 바뀐 내용을 보여준다

### B-07-2 내 게시글 삭제

> 확인 후 삭제하고, 이 게시글로 열린 채팅방에 삭제 안내를 남긴다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-07 | P-07-03 | 1-01 · 1-03 · 5-04 ⋮ 메뉴 |


- **예외 · 제약:**
  - 예약중 게시글은 약속을 취소한 뒤에 삭제할 수 있다.
  - 교환 완료 게시글은 삭제할 수 없다.
- **비고:** 10/20: 대기 요청 자동 거절 · 요청 자동 취소 삭제 (요청 단계 삭제)

**진입** 내 게시글 상세 ⋮ · 홈 내 게시글 카드 ⋮ · 내 게시글 관리(5-04) ⋮에서 삭제를 누른다

**동작**
1. 확인 팝업을 띄운다.
   - 확인 팝업 "게시글을 삭제할까요?" / "삭제하면 되돌릴 수 없습니다." [취소] [삭제하기]를 보여준다 (하이파이대로, 11/23).
   - 연결된 채팅방이 있어도 팝업은 같다. 채팅방에는 삭제 안내가 자동으로 올라간다.
2. 게시글을 삭제하고 홈 목록 · 검색에서 뺀다.
3. 이 게시글로 열린 채팅방에는 "게시글이 삭제됐어요" 시스템 메시지를 남기고 상단 카드를 "삭제된 게시글"로 바꾼다 (대화는 유지).
4. 내가 보낸 요청에서 이 게시글의 제품 카드를 "삭제된 제품"으로 바꾸고, 약속의 교환할 제품 목록에서 뺀다 (10/26). 그 채팅방에 내 쪽 자동 메시지 "'제품명'을 삭제했어요"(버튼 없음)를 남기고, 상단 카드는 남은 제품으로 다시 계산한다 (E-01-3, 10/27).

**조건**
- 교환 가능 상태일 때만 삭제할 수 있다.
- 삭제 안내 · 자동 메시지 · 알림은 상대가 아직 채팅방에 남아 있는 방에만 보낸다.
- 채팅방은 그대로 두고 대화도 된다. 약속 잡기만 막는다 (E-11-1).
- 확정 전 약속 제안에 삭제한 게시글이 교환할 제품으로 들어 있으면 그 제안은 자동 취소하고 채팅방에 안내를 남긴다. 취소 뒤 상대가 수락하면 실패한다 (E-03-2).
- 확인 팝업 문구는 한 가지다 (11/23, 하이파이대로). 연결된 방(이 게시글로 받은 요청 방 · 이 게시글을 첨부해 보낸 요청 방)은 상대가 아직 남아 있는 방이다.

| 예외 상황 | 처리 |
|---|---|
| 예약중 | 삭제를 막고 "약속을 먼저 취소해 주세요"를 보여준다 |
| 교환 완료 | 삭제 메뉴를 보여주지 않는다 |
| 처리 실패 | 공통 오류를 보여준다 (P-07-03) |

**결과** 내 게시글 관리(5-04)로 이동하고, 토스트 "삭제했어요"가 뜬다

**조건**
- 현장 모드가 켜져 있을 때만 메뉴가 보인다.

|---|---|
| 이미 시간이 끝남 | 메뉴를 숨긴다 |

**결과** 상세에 그대로 머물고, 현장 모드 배지가 사라진다

### B-08-1 게시글 상태 자동 변경

> 약속 확정 · 교환 완료 · 약속 취소에 따라 게시글 상태를 자동으로 바꾼다

| 상태 | MVP | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|
| 확정 | 포함 | P0 | REQ-B-08 | - | 1-03, 5-04 |

- **예외 · 제약:**
  - 사용자가 직접 바꿀 수 있는 건 교환 가능 → 교환 완료 하나뿐이다 ([교환 완료로 바꾸기], G-02-3).
  - 예약중은 직접 바꿀 수 없다 (약속과 묶여 있다).

**진입** 시스템 처리

**동작**

| 이벤트 | 게시글 상태 |
|---|---|

| 약속 확정 (E-04-1) | 교환 가능 → 예약중 |

**결과** 목록 · 상세 · 내 게시글 관리 배지에 바로 반영된다
