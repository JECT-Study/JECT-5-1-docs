### B-01-1 교환글 템플릿 입력

> 지금 교환 / 일반 교환을 고른 뒤, 정해진 항목을 단계별로 입력해 교환글을 작성한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-B-01 | P-02-01 | 1-06 |

- **예외 · 제약:** 1게시물 1아이템 · 필수 항목 없이 게시 불가
- **비고:** 11/12: 하이파이 반영 — 항목 이름 "제목" → "제품명"(하이파이 · 교환폼과 통일, 홈 카드 · 상세에서 제목처럼 보이는 값은 그대로). 10/19 PM·PD 회의: 단계 분리 · 카테고리 "애니" → "캐릭터". 단계 화면 · 항목 순서는 PD 시안. v0.4 (10/26): 교환 개수 항목 삭제 · '나중에 교환' → '일반 교환'. v0.5.3 (10/31): 교환 개수는 10/26 결정대로 없음 (와이어프레임에 남은 칸은 수정 필요로 표시) · 상품 상태 = 미개봉 / 개봉 하나 필수, 하자는 설명에 (교환 요청 폼과 같게)

**진입** 홈 글쓰기 버튼(FAB) · 가입 완료 [첫 교환글 올리기] · 빈 화면 [글쓰기]

**동작**
1. 먼저 지금 교환(현장 모드, B-04-1) / 일반 교환을 고른다
2. 단계별로 입력한다: 내 굿즈(1\~5 · 10) → 받고 싶은 굿즈(6) → 희망 장소(8). 단계 화면 구성 · 설명칸 위치는 PD 시안

| # | 항목 | 필수 | 입력 방식 |
|---|---|---|---|
| 1 | 사진 | 필수 | 1\~5장, 첫 장이 대표 (B-01-2) |
| 2 | 제품명 | 필수 | 자유 입력 2\~40자. 한 줄 고정, 40자에 닿으면 더 늘지 않고 이어서 치면 마지막 글자가 새 글자로 바뀜 (교환폼 C-06-2와 같음) |
| 3 | 카테고리 | 필수 | 칩 하나 선택: 캐릭터 / 아이돌(케이팝) / 스포츠 / 기타 |
| 4 | 태그 | 선택 | # 입력, 최대 5개 (B-02-1) |
| 5 | 상품 상태 | 필수 | 칩: 미개봉 / 개봉 중 하나가 항상 선택된 상태 (처음 미개봉). 하자는 설명에 |
| 6 | 원하는 아이템 | 필수 | 자유 입력 1\~50자 또는 [아무거나 상관없어요] |
| 8 | 희망 장소 | 필수 | 희망 장소 선택 화면 (B-03) |
| 9 | 현장 모드 | 선택 | 첫 단계에서 "지금 교환"을 고르면 켜짐 + 유지 시간 (B-04-1) |
| 10 | 설명 | 선택 | 자유 입력 0\~1,000자. 1,000자에 닿으면 더 늘지 않고 이어서 치면 마지막 글자가 새 글자로 바뀜 (교환폼 C-06-2와 같음). 1차 에러 없음 (금지어 경고 B-05-1은 2차) |

**조건**
- 입력 방식은 확정. 항목 순서는 PD 컴포넌트 수정에 따라 바뀔 수 있다
- 1게시물 1아이템
- 교환 개수(1개씩 / 여러 개) 항목은 없다 (10/26). 몇 개를 줄지는 요청자가 내 글을 여러 개 붙여 정하고(C-06-2), 실제 교환할 물건은 약속 때 고른다(E-03-1). 게시자 선호는 채팅에서 조율
- 입력하는 동안 필수 항목 검사(B-06-1)가 동작. 금지어 경고(B-05-1)는 2차

| 예외 상황 | 처리 |
|---|---|
| 작성 중 [그만두기] · 뒤로 가기 | "작성 중인 글이 사라져요" 확인 팝업 (임시저장은 P1) |
| 이용 제한 중 | 글쓰기 대신 사유 · 해제일 · 문의 안내 (P-05-05) |

**결과** 작성 완료 → 게시(B-06-2)

### B-01-2 사진 선택 · 앱 안 촬영

> OS 기본 사진 선택 창에서 고르거나 앱 안에서 촬영해 사진 1\~5장을 올린다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-B-01 | P-02-01 | 1-07 |

- **예외 · 제약:** 5장이 차면 더 추가할 수 없음 · 앨범(사진) 권한 요청 없음
- **비고:** v0.4 (10/26): PD 시안 반영 — 요청 아이템 장수는 교환글과 같은 1\~5장으로 확정. 11/11: 앱이 직접 만든 사진 그리드 화면 → **OS 기본 사진 선택 창**으로 변경 (FE 답변 · PM 결정). 이유 = 앨범 권한이 필요 없어 권한 거부 · 일부 사진만 허용 예외가 사라짐, 세 진입점을 공통 기능 하나로 구현 (FE: Expo expo-image-picker)

**진입** 교환글 작성 사진 칸 · 교환폼(새로 작성하기) 사진 칸 · 채팅 + 메뉴 사진 (같은 기능 재사용)

**동작**
1. 사진 칸(또는 채팅 + 메뉴 사진)을 누르면 바텀시트(1-07): 위쪽 안내 "실물을 직접 찍어주세요, 첫 장이 대표 사진이 돼요" + [앨범에서 선택] / [카메라로 촬영]
2. [앨범에서 선택] → OS 기본 사진 선택 창. 여러 장 고를 수 있고, 고를 수 있는 장수는 남은 장수(5 − 이미 붙인 장수)까지
3. [카메라로 촬영] → 카메라 실행, 찍은 사진 1장 추가 (카메라 권한은 N-03-3)
4. 고르거나 찍으면 호출한 화면으로 돌아가 채워진다. 첫 장이 대표 사진

**조건**
- 교환글 · 교환폼은 1\~5장. 실물을 직접 찍도록 안내 (IP 회피, P-02-01)
- 5장 제한은 OS 선택 창의 선택 수 제한 + 앱에서 기존 첨부 수를 포함해 한 번 더 검사
- 사진 그리드 · 정렬 · 앨범 바꾸기 등 선택 화면 구성은 OS 기본 창을 따른다

| 예외 상황 | 처리 |
|---|---|
| 이미 5장인데 사진 칸을 누름 | 토스트 "이미지는 최대 5장까지 첨부할 수 있어요" (시트를 열지 않음) |
| 지원하지 않는 형식 · 용량 초과 | 토스트 "올릴 수 없는 사진이에요" |
| OS 선택 창 · 카메라에서 취소 | 아무것도 바뀌지 않고 호출한 화면으로 |
| 카메라 권한 거부 | N-03-3 |

**결과** 호출한 화면에 사진이 채워짐

**미결정**
- [개발 확인] 장당 용량 · 압축 기준 (REQ-N-10)
- [개발 확인] OS 선택 창에서 고른 순서가 첨부 순서로 유지되는지 (첫 장 = 대표 사진)

### B-02-1 태그 입력 · 자동완성

> #으로 태그를 달고, 입력한 글자가 들어간 기존 태그를 사용 횟수순으로 추천받는다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 2차 | P1 | REQ-B-02 | P-02-02, P-02-04 | 1-06 |

- **예외 · 제약:** 선택 입력 · 최대 5개 · 1개당 1\~20자 · 중복 불가 · 금지어 태그는 경고만 (막지 않음, B-05-1)
- **비고:** 자동완성은 2차 배포 (10/20). 태그 금지어 경고도 2차

**진입** 교환글 작성 · 수정 태그 칸

**동작** (번개장터 태그 입력 방식)
1. 태그 입력칸에 글자를 입력하면 앞에 #이 붙는다
2. 입력한 글자가 들어간 기존 태그를 사용 횟수 많은 순으로 보여준다 (사용 횟수 숫자는 표시하지 않음, v0.5.3 와이어프레임 기준)
3. 목록에서 고르면 태그가 칩으로 붙고, 입력칸이 비워져 바로 다음 태그를 입력할 수 있다
4. 목록에 없으면 "#○○ 새 태그로 추가"를 누르거나 엔터 · 띄어쓰기로 추가
5. 칩의 ✕로 삭제
6. 게시하면 태그가 저장되고 사용 횟수가 반영된다

**조건**
- 선택 입력, 글당 최대 5개, 태그 1개당 1\~20자
- 사용 횟수 = 그 태그가 달린 교환글 수 (삭제된 글 제외, 교환 완료 글 포함). 0개인 태그는 추천하지 않음
- 추천 순서 = 사용 횟수 많은 순, 같으면 이름순. 기본 10개 · 최대 20개 (몇 줄 보일지는 FE)
- 모든 사용자에게 같은 기준으로 추천 (개인화 없음)
- 태그는 검색(C-03-1) · 키워드 알림(G-05-2) 매칭 대상

| 예외 상황 | 처리 |
|---|---|
| 5개 다 참 | 입력칸 비활성 "태그는 5개까지 달 수 있어요" |
| 20자 초과 | 더 입력되지 않음 |
| 같은 태그 중복 | 추가하지 않음 |
| 금지어 포함 | 추가는 되고 칸 아래 경고만 (B-05-1). 금지어가 든 태그는 추천 목록에 나오지 않음 |
| 자동완성 조회 실패 | 목록 없이 입력은 계속 가능 |

**결과** 상세(1-03)에 태그 표시

**미결정**
- [개발 확인] 사용 횟수가 같을 때 2차 정렬 · 삭제된 글 집계 여부

### B-03-1 장소 검색

> 장소를 입력하면 그 위치로 핀이 잡히고, 입력한 이름이 만날 곳 이름이 된다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-B-03 | P-03-01, P-07-03 | 1-08 |


- **예외 · 제약:** 찾는 장소가 없으면 지도에서 핀을 직접 맞춤
- **비고:** 개발 확인 안건 6번: 네이버 지도 API로 역 · 가게 · 주소 모두 가능 (지역 검색 + Geocoding 결과 통합)

**진입** 희망 장소 선택(1-08) 화면 위 검색창 "장소 검색 (역 · 가게 · 주소)"

**동작**
1. 장소를 입력한다 (예: 서울역 1번 출구). 입력하면 바로 일치하는 장소 목록이 나온다 (자동완성). [검색] 버튼은 키보드만 내리고 목록은 그대로 (v0.5.3 10/31)
2. 네이버 지도 API(지역 검색 + Geocoding)로 역 · 가게 · 주소를 찾아 지도 핀을 그 위치로 옮긴다
3. 결과가 여러 개면 목록에서 고르고, 고른 위치로 핀이 옮겨진다. 목록에는 장소 이름 · 주소 · 거리 · 분류 (거리는 현재 위치 기준, 위치 권한이 없으면 숨김)
4. 입력한 장소명이 만날 곳 이름에 채워진다 (수정 가능)
5. 핀 위치를 확인하고 [이 위치로 설정]

**조건**
- 입력 2\~30자, 줄바꿈 불가
- 검색한 장소도 반드시 핀(좌표)으로 저장된다. 그래서 모든 글이 탐색 위치 설정 1km · 가까운순 · 거점 분류에 쓰일 수 있다. 탐색 위치 설정 지도 검색(C-01-1)도 이 기능을 재사용

| 예외 상황 | 처리 |
|---|---|
| 찾는 장소가 없음 | "위치를 찾지 못했어요. 지도를 움직여 핀을 맞춰 주세요" + 입력한 이름은 만날 곳 이름으로 유지 |
| 2자 미만 | "장소를 2자 이상 입력해 주세요" |
| 검색 실패 (네트워크) | 공통 오류 (P-07-03) |

**결과** 작성 화면 희망 장소 칸에 "장소명 · 만날 곳 이름" 표시. 거점 분류는 핀 좌표로 자동 (B-03-2)

### B-03-2 지도 핀 · 현재 위치 · 만날 곳 이름

> 지도 핀이나 현재 위치로 위치를 정하고, 만날 곳 이름을 덧붙인다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-B-03, REQ-N-04 | P-03-01, P-03-02, P-02-04 | 1-08 |

- **예외 · 제약:** 현재 위치는 조회만, 서버에 저장하지 않음
- **비고:** 10/19 개발 확인 안건 1번: 핀이 거점 다각형 안이면 자동 분류 · 밖이면 미분류, 거점 선택 칩 없음

**진입** 희망 장소 선택(1-08) 지도 · [📍 현재 위치로 설정]

**동작**
1. 지도 가운데 고정 핀, 지도를 움직여 위치를 정한다
2. [현재 위치로 설정] → 위치 권한 확인(N-03-2) 후 핀을 현재 위치로 옮긴다
3. 핀 아래 "만날 곳 이름"을 적는다 (예: 홍대입구역 9번 출구)
4. [이 위치로 설정] → 좌표 · 만날 곳 이름 저장. 핀이 거점 다각형 안이면 그 거점, 밖이면 미분류 (거점 선택 칩 없음)

**조건**
- 시작 위치: 위치 권한이 있으면 현재 위치, 없으면 홍대 거점
- 만날 곳 이름은 선택, 2\~30자 (예: 1층, 9번 출구). 비워두면 검색한 장소 이름 또는 "선택한 위치"로 표시
- 사용자 현재 위치는 저장하지 않고, 희망 장소 좌표만 글에 저장 (REQ-N-04)

| 예외 상황 | 처리 |
|---|---|
| 위치 권한 거부 | "장소 검색이나 지도 핀으로 직접 설정해 주세요" |
| 현재 위치를 못 가져옴 | "현재 위치를 찾지 못했어요" |
| 지도 로딩 실패 | [다시 시도] + [목록에서 고르기] |

**결과** 작성 화면 희망 장소 칸에 "장소 이름 · 만날 곳 이름" 표시. 교환글 상세에는 장소 이름(검색한 경우) 또는 구 + 동 + 번지(핀만 옮긴 경우)와, 지도 아래 만날 곳 이름이 보인다 (C-05-1, 10/27)

### B-04-1 지금 교환(현장 모드) 설정 · 자동 해제

> 지금 교환을 켜고 유지 시간을 정하면 그 시간 동안 "지금 교환" 배지로 노출되고, 끝나면 일반 교환 글로 바뀐다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|

### B-07-2 내 교환글 삭제

> 확인 후 삭제하고, 이 글로 열린 채팅방에 삭제 안내를 남긴다

- **비고:** 10/20: 대기 요청 자동 거절 · 요청 자동 취소 삭제 (요청 단계 삭제)

**진입** 내 교환글 상세 ⋮ · 홈 내 글 카드 ⋮ → 삭제

**동작**
1. 확인 팝업: 이 글과 연결된 채팅방(이 글로 받은 요청 방 · 이 글을 첨부해 보낸 요청 방)이 있으면 "삭제할까요? 이 글과 연결된 채팅방에 삭제 안내가 가요", 없으면 "삭제할까요?"
2. (11/6 삭제: 첨부된 경우 추가 문구 → 1번 문구 하나로 합침)
3. 글을 삭제하고 홈 목록 · 검색 · 탐색 위치 설정 숫자에서 뺀다
4. 이 글로 열린 채팅방에는 "교환글이 삭제됐어요" 시스템 메시지를 남기고 상단 카드를 "삭제된 글"로 바꾼다 (대화는 유지)
5. 내가 보낸 요청의 아이템 카드에서 이 글 줄을 "삭제된 아이템"으로 바꾸고, 약속의 교환할 물건 목록에서 뺀다 (10/26). 그 채팅방에 내 쪽 자동 메시지 "'글 제목'을 삭제했어요"(버튼 없음)를 남기고, 상단 카드는 남은 아이템으로 다시 계산한다 (E-01-3, 10/27)

**조건**
- 교환 가능 상태일 때만 삭제 가능
- 삭제 안내 · 자동 메시지 · 알림은 상대가 아직 채팅방에 남아 있는 방에만 보낸다
- 채팅방은 그대로 두고 대화도 된다. 약속 잡기만 막는다 (E-11-1)
- 확정 전 약속 제안에 삭제한 글이 교환할 물건으로 들어 있으면 그 제안은 자동 취소하고 채팅방에 안내를 남긴다. 취소 뒤 상대가 수락하면 실패 (E-03-2)
- 확인 팝업 문구는 연결된 채팅방이 있는지만 본다. 받은 요청 방과 첨부해 보낸 요청 방을 나누지 않는다 (둘 다 결과가 "연결된 방에 삭제 안내"로 같음, 11/6 PM). 연결된 방 = 상대가 아직 남아 있는 방

| 예외 상황 | 처리 |
|---|---|
| 예약중 | 삭제를 막고 "약속을 먼저 취소해 주세요" |
| 교환 완료 | 삭제 메뉴를 보여주지 않음 |
| 처리 실패 | 공통 오류 (P-07-03) |

**결과** 내 교환글 관리(5-04)로 이동, 토스트 "삭제했어요"

- 현장 모드가 켜져 있을 때만 메뉴 노출
- 끈 뒤 다시 켜기 · 시간 연장은 MVP 제외

| 예외 상황 | 처리 |
|---|---|
| 이미 시간이 끝남 | 메뉴 숨김 |

**결과** 상세 유지, 현장 모드 배지 제거

### B-08-1 교환글 상태 자동 변경

> 약속 확정 · 교환 완료 · 약속 취소에 따라 글 상태를 자동으로 바꾼다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-B-08 | - | 1-03, 5-04 |

- **예외 · 제약:** 사용자가 직접 바꿀 수 있는 건 교환 가능 → 교환 완료 하나뿐 ([교환 완료로 바꾸기], G-02-3). 예약중은 직접 바꿀 수 없음 (약속과 묶여 있음)

**진입** 시스템 처리

**동작**

| 이벤트 | 글 상태 |
|---|---|
| 게시 | 교환 가능 |
| 약속 확정 (E-04-1) | 교환 가능 → 예약중 |
| 약속 취소 · 노쇼 신고 (E-07 · E-08 · F-04) | 예약중 → 교환 가능 |
| 교환 완료 (F-01-2) | 예약중 → 교환 완료 |
| 교환 완료로 바꾸기 (G-02-3) | 교환 가능 → 교환 완료 |
| 운영자가 자동 완료를 되돌림 (H-03-4) | 교환 완료 → 교환 가능 |

**조건**
- 교환이 완료되면 약속에서 교환할 물건으로 고른 첨부 글만 함께 교환 완료 (고르지 않은 첨부 글은 교환 가능 그대로)
- 예약중이면 새 요청을 받지 않음

**결과** 목록 · 상세 · 내 교환글 관리 배지에 바로 반영
