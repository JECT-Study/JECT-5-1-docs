### F-01-1 교환 확인 질문

> 약속 30분 뒤 양쪽에 교환했는지 묻고, 한 명만 "교환했어요"라고 답해도 완료로 넘긴다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-F-01 | P-07-04, P-07-03 | 2-02, 2-02g |

- **예외 · 제약:** 응답이 엇갈리면 완료 우선 · 이의는 신고 · 문의로 따로 제기
- **비고:** 10/19: 버튼 "교환 못 했어요" → "못 만났어요" (PD 시안)

**진입** 약속 시각 30분 뒤 (시스템)

**동작**
1. 양쪽에 푸시 + 채팅방 카드 "🤝 교환 잘 하셨나요? 한 명만 답해도 처리돼요"
2. [교환했어요] → 교환 완료 처리(F-01-2)
3. [못 만났어요] → 이유 선택(F-04-1)
4. 응답 없음 → 리마인드 · 자동 완료(F-03-1)
5. [제안] 약속이 확정되면 채팅방 상단 카드에 [교환했어요]를 바로 보여줘, 약속 시각 전에도 완료할 수 있다

**조건**
- 한 명이 답하면 다른 사람 카드도 결과가 반영된 상태로 바뀐다
- 응답은 1인 1회, 바꿀 수 없다

| 예외 상황 | 처리 |
|---|---|
| 응답이 엇갈림 (교환했어요 vs 못 만났어요) | 완료로 처리. 이의는 신고 · 문의(G-08-1)로 |
| 상대가 먼저 "교환했어요" | 내 카드가 "교환이 완료됐어요"로 바뀜 ([후기 남기기]는 2차) |
| 처리 실패 | 공통 오류 (P-07-03) |

**결과** 완료 또는 못 만남(이유 기록) 중 하나로 정리

### F-01-2 교환 완료 처리

> 교환글과 약속에서 고른 첨부 글을 교환 완료로 바꾸고, 완료 횟수를 올린다 (후기는 2차)

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-F-01, REQ-F-02 | P-01-01, P-07-02 | 2-02g |

- **예외 · 제약:** 되돌릴 수 없음 · 약속 확정 없이 완료 불가
- **비고:** 매너 지표 반영 · 후기 요청은 2차 (10/20). v0.4 (10/26): 약속에서 고른 첨부 글만 완료 · 후기 화면은 PD가 '2차' 표시로 그려 둠

**진입** [교환했어요] → 완료 처리 시트 [완료하기] · 자동 완료(F-03-1)

**동작**
1. 시트 안내 "한쪽만 확정해도 교환 완료 처리돼요 · 확정은 취소할 수 없어요" (문구 PD 시안)
2. 약속 · 교환글 · 약속에서 고른 첨부 글을 교환 완료로 한 번에 처리. 약속에서 고르지 않은 첨부 글은 교환 가능으로 남는다 (10/26). 새로 작성한 아이템은 글이 아니라 처리할 것 없음
3. 양쪽 교환 완료 횟수 +1, 매너 지표 반영
4. 같은 글의 다른 채팅방 입력 종료 (F-02-1)
5. 교환 내역(5-07)에 기록, 상대에게 후기 요청 알림

| 예외 상황 | 처리 |
|---|---|
| (고른 첨부 글은 약속 확정 때 예약중이 되므로 다른 곳 예약 충돌은 생기지 않음, E-04-1) 고르지 않은 첨부 글 | 영향 없음, 교환 가능 유지 |
| 처리 실패 | 응답은 저장하고 서버에서 다시 시도 [개발 확인] |

**결과** 응답한 사람 → 후기(2-03). 상대 채팅방 카드 "교환이 완료됐어요 [후기 남기기]"

### F-02-1 다른 채팅방 입력 종료

> 교환이 완료되면 같은 글의 다른 채팅방에 안내하고 입력을 닫는다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-F-02 | - | 2-02 |

- **예외 · 제약:** 대화 내용은 계속 볼 수 있음

**진입** 시스템 처리 (F-01-2)

**동작**
1. 같은 글의 채팅방 중 교환이 완료된 방을 뺀 나머지에 "이 교환글은 다른 분과 교환이 완료됐어요"
2. 입력창을 "교환이 완료된 글이라 메시지를 보낼 수 없어요"로 바꾼다

**조건**
- 교환한 당사자 채팅방은 완료 후에도 대화를 계속할 수 있다 (하자 등 사후 연락). 교환 내역(5-07)에서도 들어갈 수 있다

| 예외 상황 | 처리 |
|---|---|
| 화면이 바뀌기 전에 전송 시도 | 서버에서 거부, 입력창을 안내 문구로 교체 |

**결과** 다른 채팅방 읽기 전용

### F-03-1 리마인드 · 자동 완료

> 양쪽 모두 답하지 않으면 24시간 뒤 리마인드하고, 3일 뒤 자동으로 교환 완료 처리한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-F-03 | P-01-01, P-07-04 | 2-02g |

- **예외 · 제약:** 한 명이라도 응답하면 대상 아님 · 노쇼 신고가 있으면 자동 완료 안 함

**진입** 시스템 처리 (스케줄)

**동작**
1. 교환 확인 질문 뒤 24시간 동안 양쪽 모두 답이 없으면 리마인드 "{닉네임}님과 교환 잘 하셨나요? 결과를 알려주세요"
2. 3일 뒤에도 답이 없으면 자동 완료 (F-01-2와 같은 처리 + 자동 완료 표시)

**조건**
- 자동 완료도 완료 횟수 · 글 상태에 똑같이 반영. 매너 지표에는 반영하지 않는다

| 예외 상황 | 처리 |
|---|---|
| 리마인드 전에 한쪽이 답함 | 리마인드 보내지 않음 |
| 노쇼 신고가 접수돼 있음 | 자동 완료하지 않음 |

**결과** 자동 완료, 양쪽에 후기 요청

### F-04-1 교환 못 한 이유 선택

> [못 만났어요]를 누르면 이유 5개 중 하나를 고른다. 1차는 기록만, 2차에 매너 지표 반영

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 1차 | P0 | REQ-F-04 | P-01-01 | 2-02g |

- **예외 · 제약:** 서로 취소는 매너 지표 영향 없음 · 고른 이유는 상대에게 비공개
- **비고:** 10/19 PM·PD 회의 · PD 시안: 실패 사유 5개 (10/20 PM 확정). 실패 정책 깊은 논의는 기획 발표 뒤

**진입** 교환 확인 카드 [못 만났어요]

**동작**
1. 이유 선택 시트

| 이유 | 1차 처리 | 2차 처리 |
|---|---|---|
| 연락 없이 안 나왔어요 | 기록 저장, 약속 취소 · 글 교환 가능 | 노쇼 신고(F-04-2) → 운영자 확인 후 매너 지표 반영 |
| 물품이 달라요 | 기록 저장, 약속 취소 · 글 교환 가능 | 운영자 확인 후 매너 지표 반영 |
| 금품을 요구했어요 | 기록 저장, 약속 취소 · 글 교환 가능 | 운영자 확인 후 매너 지표 반영 |
| 서로 약속을 취소했어요 | 확인 팝업 "매너 지표에는 영향이 없어요" → 약속 취소 | 같음 (매너 지표 영향 없음) |
| 직접 입력 (0\~100자) | 기록 저장, 약속 취소 · 글 교환 가능 | 운영자가 DB에서 확인 |

2. 상대에게 "약속이 취소됐어요" 알림 (고른 이유는 상대에게 보이지 않음)

**조건**
- 하나를 골라야 [다음] 활성
- 1차는 매너 지표가 없어서 기록만 남긴다. 기록은 2차 매너 지표 · 노쇼 처리에 쓴다

**결과** 약속 취소, 글 교환 가능, 이유 기록

### F-04-2 노쇼 신고

> 약속 장소에 오지 않은 상대를 신고하고, 노쇼 기록은 공개하지 않는다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 2차 | P0 | REQ-F-04, REQ-N-02 | P-01-03, P-05-02, P-05-03 | 2-04 |

- **예외 · 제약:** 약속 시간 전 신고 불가 · 한 약속에 1회 · 노쇼 기록 비공개
- **비고:** [논의] 진입 경로: 교환 확인에서만 vs 신고하기(사유 노쇼)에서도

**진입** 교환 못 한 이유 "상대가 약속 장소에 오지 않았어요" (F-04-1)

**동작**
1. 확인 "{닉네임}님을 노쇼로 신고할까요? 추가 설명은 상대에게 공개되지 않아요" + 추가 설명(선택, 0\~300자)
2. 신고를 접수하고 글을 교환 가능으로 되돌린다
3. 운영자가 DB에서 확인해(하루 1회, REQ-N-06) 인정하면 노쇼한 사람의 매너 지표에 반영. 확인 전에는 반영 보류

**조건**
- 노쇼 횟수는 다른 사용자에게 공개하지 않음. 본인은 내 프로필에서 확인 (G-03-1)
- 노쇼 누적 제한: 90일 안 인정 2회 7일 · 3회 30일 (P-05-02, MVP 적용 [논의])
- 허위 신고로 판단되면 신고자 매너 지표 −10 (P-05-03)

| 예외 상황 | 처리 |
|---|---|
| 상대가 이미 "교환했어요"로 답함 | 완료가 우선 (F-01-1). 노쇼 주장은 문의(G-08-1)로 |
| 같은 약속 중복 신고 | "이미 신고했어요" 안내 |

**결과** 채팅방에 "노쇼 신고를 접수했어요 · 글이 다시 교환 가능으로 바뀌었어요"

**미결정**
- [논의] 신고하기 메뉴(사유: 노쇼)에서도 들어올 수 있게 할지

### F-05-1 후기 남기기

> 교환 후 별로예요 / 좋아요 / 최고예요 중 하나로 후기를 남기거나 건너뛴다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| 확정 | 포함 | 2차 | P0 | REQ-F-05 | P-01-01, P-04-03 | 2-03 |

- **예외 · 제약:** 비공개 · 교환 1건당 1개 · 수정 · 삭제 불가
- **비고:** 평가 단계: 3단계 (기획) vs 좋아요 / 별로예요 (PD 시안) [논의]

**진입** "교환했어요" 직후 · 후기 요청 알림 · 채팅방 [후기 남기기] · 교환 내역 [후기 보내기]

**동작**
1. 3단계 중 하나를 고르면 [보내기] 활성, [건너뛰기]는 항상 가능
2. 저장하고 매너 지표에 반영

**조건**
- 후기는 상대에게 공개하지 않음. 받은 후기는 본인만 내 프로필에서 단계별 개수로 확인
- 보낸 후기는 수정 · 삭제 불가
- 작성 가능 기간 교환 완료 후 7일
- "별로예요" 이유 수집은 MVP 제외 (후순위)

| 예외 상황 | 처리 |
|---|---|
| 이미 남김 | 버튼 "후기 완료" 비활성 |
| 기간 지남 | "후기 작성 기간이 지났어요" |

**결과** 토스트 "후기를 보냈어요"

### F-06-1 매너 지표 계산 · 표시

> 완료 · 노쇼 · 후기 · 임박 취소로 매너 지표를 계산하고, 지표와 완료 횟수만 공개한다

| 상태 | MVP | 배포 | 우선순위 | 요구사항 | 정책 | 화면 |
|---|---|---|---|---|---|---|
| **논의** | 포함 | 2차 | P0 | REQ-F-06 | P-01-01, P-01-02, P-01-04 | 1-05, 5-02, 5-05 |

- **예외 · 제약:** 노쇼 · 후기 평가는 비공개 · 교환 0회면 지표 대신 안내 문구
- **비고:** [회의] 매너 지표 이름 · 표시 형식

**진입** 시스템 처리 · 프로필 · 요청 카드 표시

**동작**
1. 아래 이벤트가 생기면 지표를 다시 계산

   | 이벤트 | 반영 |
   |---|---|
   | 교환 완료 | 올림 |
   | 후기 | 단계에 따라 |
   | 노쇼 (신고 인정) | 내림 |
   | 임박 일방 취소 | 내림 |
   | 합의 취소 · 서로 취소 · 제안 만료 | 영향 없음 |

2. 게시자 프로필 · 내 프로필 · 요청 카드에 지표와 완료 횟수 표시

**조건**
- 계산식 · 초기값은 정책서 P-01-02 ([제안] 시작 50 · 완료 +2 · 최고예요 +2 · 좋아요 +1 · 별로예요 −1 · 임박 취소 −5 · 노쇼 −10)
- 노쇼 이의가 인정되면 지표 복구 (P-01-04)

**결과** 지표 표시

**미결정**
- [논의] 이름 · 표시 형식 (숫자 / 단계)
- [제안] 계산식 · 초기값 (P-01-02)
